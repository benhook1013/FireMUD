# Issuer Authority gRPC mTLS Test Certificates

PUBLIC TEST KEYS ONLY. These certificates and private keys exist only to prove the Account issuer-authority gRPC peer-identity boundary in tests. Never use or mount them as runtime or deployed credentials. Production material must be issued separately.

The fixture CA signs leaves with one exact FireMUD SPIFFE URI SAN each. `account.crt` identifies `spiffe://firemud/ns/test/sa/account-service`; `game-session.crt` identifies `spiffe://firemud/ns/test/sa/game-session-service`; `wrong-service.crt` identifies `spiffe://firemud/ns/test/sa/game-design-service`; `wrong-namespace.crt` identifies `spiffe://firemud/ns/other-test/sa/game-session-service`; and `wrong-account-namespace.crt` identifies `spiffe://firemud/ns/other-test/sa/account-service`. The wrong-service and wrong-namespace leaves provide trusted but unauthorized clients; the Account leaf with the wrong namespace provides a trusted server identity with only the namespace changed. Every leaf also has `DNS:localhost` and `IP:127.0.0.1` SANs for the loopback socket. Leaves are valid for both TLS server and client authentication.

The fixtures were generated together with OpenSSL as a test-only CA and RSA leaf keypairs. The CA private key was not retained in the fixture directory. All leaves expire on `2036-09-29` UTC; regenerate this set before that date if the tests remain in use. Verify each leaf with `openssl verify -CAfile ca.crt <leaf>.crt`, inspect URI SANs with `openssl x509 -in <leaf>.crt -noout -ext subjectAltName`, and confirm leaf key usage with `openssl x509 -in <leaf>.crt -noout -ext extendedKeyUsage` after regeneration.
