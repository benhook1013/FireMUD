# Development Certificates

This directory contains the helper scripts for local development TLS material.

Generated certificate outputs in this directory are ignored by Git and should not be committed.

## Script Map

- `dev-tools/certs/generate-dev-certs.sh` writes into `dev-tools/certs/` when no explicit target is provided.
- When the complete generic bundle already exists, the generator validates the CA/key pair, shared client/server leaves and key pairs, trust, purposes, local SANs, and `dev-*` aliases. Invalid existing material fails closed without changing or rotating the CA or issued leaves; diagnose it or deliberately back up/discard the generated set before reissuing. The cleanup helper removes only its listed files and known workload/projection paths, preserving and reporting unexpected files and symlinks.
- `dev-tools/certs/generate-dev-certs.sh --workload` signs local development or test-only leaves for the five publication services, Account, Game Session, and Social Groups with the exact SPIFFE URI and service DNS SANs. Workload keys remain mode `0600`; `ensure-dev-certs.sh` changes permissions only in its ignored local runtime projection. Hosted preview and dev-demo use issuer-projected runtime leaves, not this local signing path.
- Standalone hosted runs keep the legacy shared bundle for other gRPC workloads and use eight cert-manager-issued `firemud-grpc-<workload>` runtime-facing leaf Secrets: five publication workloads, Account, Game Session, and Social Groups. Runtime namespaces contain no CA private key; missing or invalid issuer-projected leaves fail closed.
- Default `dev-tools/certs/ensure-dev-certs.sh` validates the local CA and shared material, then prepares the canonical local Compose entrypoints with distinct Account, Game Session, and Social Groups workload identities under the ignored `local-runtime/` projection. It contains runtime-facing material only, never `ca.key`; the host CA key remains mode `0600`.
- `dev-tools/certs/ensure-dev-certs.sh --compose-mtls <run-owned-fixture-root>` creates the canonical smoke fixture beneath the active run-owned Compose state directory. The authority directory remains host-only with mode `0700`, and its CA private key remains mode `0600`; each of eleven Java application containers gets a read-only `/app/certs` mount with only its leaf key, certificate, and public CA. Account, Game Session, Entity Management, Social Groups, and World Management get distinct `dev`-namespace SPIFFE leaves; World Management's leaf supports its authenticated Game Session owner-read path for the initial admission bind. Other services use the shared local development leaf. Retain the fixture while its exact Compose project may restart, and remove it only after that project is torn down.
- The three canonical runtime-proof entrypoints layer `docker/docker-compose.grpc-mtls.override.yml` last; ordinary `docker/docker-compose.override.yml` remains the plaintext local debugging profile. Hosted certificate provisioning is separate and never mounts the local CA private key.
- `dev-tools/certs/clean-dev-certs.sh` removes only its listed top-level files and known workload-leaf/runtime-projection paths, removing directories only when empty; unexpected files and symlinks are preserved and reported.
