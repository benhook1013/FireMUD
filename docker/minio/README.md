# Trusted MinIO Source Images

The MinIO server image builds the maintained Chainguard fork at a pinned lightweight release tag and its GitHub-verified commit. The MinIO client image builds the original upstream's pinned annotated release tag and peeled source commit. The build checks each remote tag reference and exact cloned commit before compilation, uses the digest-pinned Go builder and Alpine runtime declared by both Dockerfiles, and leaves each upstream `go.sum` read-only during compilation.

Pull request builds receive only `contents: read`. They build both images locally, verify server health, create the `firemud-assets` bucket with `mc`, and verify its anonymous policy is private. Successful develop-branch builds upload the exact smoke-tested images and image IDs. Build provenance and publisher expectations derive these image references from the trusted source Dockerfiles and fail closed if the two Dockerfiles disagree or omit a digest. A separate `workflow_run` publisher checks that the source run was a successful push to the repository's `develop` default branch, validates the source commits and image IDs, then publishes those exact image bytes and attests each pushed digest.

The publisher summary contains the immutable GHCR references. Runtime manifests and Compose configuration should use those `name@sha256:...` references. The packages must be public for the publisher's anonymous post-push pull check; it fails with the required GitHub Packages visibility action if either package is private. This PR's full-stack Smoke builds and uses the pinned sources locally, without pulling the published packages.

The Alpine runtime includes BusyBox `wget` and `sh`, but not `curl`. Server health checks should use `busybox wget` (or another tool already present in the image), and the Compose `mc` setup can continue to override the entrypoint with `sh -c`.
