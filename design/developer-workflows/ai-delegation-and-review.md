# AI Delegation And Review

Use this guide when the main thread is considering subagents or independent verification.

## Delegation

### Explicit Overseer/Worker arrangement

- When the user establishes an Astra Overseer/Worker arrangement, Astra Overseer owns project direction, priority, scope and architecture decisions, evidence adjudication, cross-task coordination, and user communication. The Overseer delegates operational repository searches and reading, provenance and comparisons, audits, implementation and documentation edits, tests and validation, and bulk tooling work to an appropriate worker or subagent. This is an explicit user preference; do not create a small-task exception for repeated operational work.
- The Overseer may use minimal task-coordination tools, inspect compact returned evidence, and perform a narrow final authorized PR metadata action, such as closing a proven redundant PR. That narrow exception does not authorize the Overseer to perform the underlying investigation or other operational work. If no worker is available, report the constraint rather than silently taking execution.
- Sol lane Workers advance unambiguous authorized steps autonomously, orchestrate substantial operational work, and delegate bounded bulk reading, coding, and repetitive testing to appropriate agents. The lane main Worker owns decomposition, integration, targeted evidence and diff review, consolidated proof decisions, final experience verification, and lane PR/review operations; do not recreate all delegated work in the main context, impose agent quotas, or fragment trivial tasks. Routine reports are nonblocking; contact Astra Overseer for a genuine consequential decision or blocker, with evidence and a proposed next action. Direct cross-task communication requires user authorization and available tools; avoid acknowledgement loops. Cross-task summaries to Astra Overseer are limited to meaningful milestones, decisions, or blockers; detailed helper output stays with the lane Worker.
- The arrangement does not require permission for each task, add governance beyond these boundaries, or grant new merge authority. Preserve the existing model-tier rules and complete prohibition text below.

### General delegation rules

- Use Luna as the default value execution model for bounded delegated work, but do not treat it as universal. Delegate to `gpt-5.6-luna` at `high` for routine bounded investigation, mechanical patches, and straightforward test updates. Use Luna at `xhigh` for substantial delegated work and independent review, and at `max` for known-hard cross-file correctness work, exhaustive audits, or a failed `xhigh` attempt. Luna reasoning levels are not approval-gated. If a subagent launch fails specifically because the selected model is at capacity, wait 30–60 seconds and retry the same model and reasoning tier before upgrading; upgrade only if capacity remains unavailable after that retry, report the failed model/tier, wait duration or retry count, and selected fallback to the human immediately when fallback starts, and repeat the capacity failure, delayed retry, and fallback in the end-of-round/status handoff.
- Treat `agent thread limit reached` as a structural harness limit, not model capacity: do not change models or use capacity retries. First list agent statuses; if an obsolete interrupted thread occupies a slot, send it a close-out message and then one bounded follow-up that performs no reads or edits and returns immediately; verify it completed, then retry the blocked spawn once. No delete/archive operation exists; do not recycle useful active threads or reuse the recovered thread when fresh-context independence is required.
- Escalate to `gpt-5.6-sol` at `medium` when broad synthesis, ambiguous or conflicting evidence, competing options, or consequential inflection analysis matters more than coding-agent throughput; it is a task-type escalation, not the automatic next tier after Luna. Repeated inconclusive Luna passes trigger routing reconsideration, not an automatic higher Luna tier. Sol at `high` is the absolute subagent ceiling and still requires explicit human approval under root guidance. Do not use Terra as a normal routing tier or delegate product or architecture design decisions.
- Delegate bounded repository investigation when it provides meaningful context or cost savings; do not delegate merely to avoid a few routine tool calls. Keep a single main-thread workflow unless a human asks otherwise.
- Every delegation prompt must pin the absolute worktree path, expected branch, exact write scope, and explicitly required validation commands. Before any edit, the prompt must require `pwd` and `git branch --show-current`, compare both results with the pinned values, and stop and report a mismatch before writing.
- Every delegation prompt must name the authoritative design, implementation-tracker, or workflow context that governs the assigned behavior. Do not make a worker infer authority from nearby code when the repository already records it explicitly.
- Documentation delegation must name the canonical contract owner and the exact local consequence expected in each secondary document. Add normative contract detail only at the owner; secondary documents retain links, local API/storage/transport/operational consequences, implementation drift, and proof status rather than becoming self-contained copies. A review request for repeated detail is not authority to duplicate it.
- For review-fix delegation, the main thread must adjudicate the finding and state the smallest intended semantic change before assigning edits. A worker must not generalize a local finding into a new validator family, parallel schema mirror, broad document rewrite, or adjacent contract expansion. If the requested fix appears to require that wider mechanism, stop and report the proposed expansion for main-thread integration instead of implementing it speculatively.
- Subagent validation is a closed allowlist. A subagent may run only the exact validation commands named in its task; prohibiting Gradle or another canonical command does not authorize standalone linters, approximations, ad hoc flags, or other substitute checks. If no validation is named, report it as deferred. The main thread runs consolidated validation after integration.
- A delegated task ends when its assigned edits and explicitly named checks are complete. Return immediately rather than adding self-selected wording passes, structural audits, cleanup, or substitute validation merely to appear thorough.
- Reuse a completed subagent only for a direct continuation of the same bounded task or domain where its retained context remains an asset. Unrelated work uses a fresh thread with a descriptive task name: retained context can bias a new assignment, and a stale sidebar identity obscures what is actually running. End-of-round reporting identifies any intentional thread reuse as well as newly spawned workers.
- Prefer a native blocking watcher or product wait primitive over repeated model polling. When progress is blocked on one external transition and no such wait exists, a cheap fresh read-only Luna sentinel may poll at low frequency and return only on state change, timeout, or required adjudication; this is most useful when the concurrency slot would otherwise be idle. Its prompt must authorize the exact read-only PR, review, or CI inspection while retaining every write prohibition.
- Every substantial round ending, handoff, or blocker report must include one short actual-delegation line naming model and tier, bounded roles, main verification, and any relevant reuse or constraint; if a substantial operational batch had no delegation, briefly state why. Do not require this in every commentary update, separate acknowledgement messages, agent-count targets, or forced model diversity. Every delegated handoff must also report changed files, explicitly named checks run or deferred, reasoning-sensitive assumptions, and unresolved concerns. A terse completion claim without that evidence is not an integration handoff.
- Every delegation prompt must repeat that the subagent must not inspect or alter review, CI, or PR state; invoke CodeRabbit CLI or hosted review; post review commands; start, stop, trigger, or rerun CI; resolve review threads; commit, push, retarget branches, open, merge, or close PRs; or otherwise perform review/CI/PR operations. Those actions remain prohibited unless the main thread explicitly delegates the exact action and any human authorization required by `AGENTS.md` is present. Delegation never authorizes merging or closing a PR without that explicit human authorization. Prompts must also repeat that subagents must not revert, delete, overwrite, stage, or commit concurrent edits outside their assigned file set; preserve unrelated dirty edits and stop only for overlapping assigned-file edits or unclear or risky intent, reporting the overlap or ambiguity.
- Before integrating delegated work, the main thread must inspect the returned diff against the assigned scope and authoritative context, reconcile interactions with concurrent or adjacent changes, and reject unrequested edits. Validation alone does not substitute for diff inspection.

## Independent Review Evidence

- For an exhaustive audit, require a per-item coverage ledger, named source and design documents read, and an incomplete-review gate. An unsupported "No findings" statement is not exhaustive evidence.
- Use hosted or CLI CodeRabbit as the default iterative PR defect-discovery and fix-verification path. Spend model-backed independent review only for a consequential initial check before CodeRabbit is available, a risk CodeRabbit cannot cover, or an explicitly requested audit.
- When model-backed review is justified, use a fresh-context reviewer at the required delegation tier. The main thread remains responsible for checking the evidence and deciding whether the review is complete.
- Do not require an additional model review on every cycle or spend subagent review tokens duplicating adequate CodeRabbit hosted or CLI coverage without a concrete risk or coverage reason. End-of-run reporting must summarize how many subagents were used, their bounded roles, and whether they changed files or only supplied evidence.
