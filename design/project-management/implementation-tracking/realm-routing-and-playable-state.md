# Realm Routing and Playable State

## Target-State Authority

This is a non-normative implementation tracker for realm routing and playable state. Canonical target-state realm visibility, admission pointers, playable-state projection, runtime target identity, and freshness contracts remain authoritative in [design/architecture](../../architecture/README.md) and the linked design sources below; this tracker owns current implementation status, proof evidence, gaps, and handoffs, not normative design.

## Current Status

The working realm-catalog projection, admission-pointer reads, bootstrap/connect-scope flow, session-freshness normalization, runtime projections, and currently live playable-state boundaries are implemented. This is not a claim that routing is fully implemented. The direct-text [REALMS-to-JOIN scope handoff](../../architecture/system-architecture-authentication.md#direct-text-realms-to-join-scope-normative) remains target-only and unimplemented; Account issuance/validation and Game Session transport-local scope retention, retry, terminal-outcome, and expiry behavior still need implementation and proof. The complete routing boundary remains partial: persisted routes require a positive runtime target and cannot represent explicit `CLOSED`; the current proto/repository key remains `{tenantId, worldSlug, realmSlug}` rather than canonical `{tenantId, realmId}`; public pointer mutation and prepared-cutover RPCs remain fail-closed; and pointer-plus-audit persistence does not establish the full prepared execution/cutover boundary. World hold, source drain, lifecycle fencing, and the target bounded active-session drain remain gaps; current active bindings are invalidated from pointer state. Public/grant policy is also partial: registered grant reads retain the legacy four-field grant without expiry or tombstones, and tenant-admin management is absent. Local lifecycle-bound Account storage retains explicit expiry, revision-ordered mutation receipts and tombstones, while management and consumer entry points remain unregistered; its proof and remaining authorization and consumer gaps are tracked in [Player Access](./player-access-and-session.md). Local initial `FRESH` lifecycle preparation exists but does not complete playtest initialization or admission. Seeded/snapshot initialization, reset, qualified end-to-end current lifecycle authority, owner manifests, generation advancement, and close/expiry orchestration remain incomplete and unproved; their target owner contracts are linked below.

## Consolidated Implementation Record

### Authority and Pointer Contract

Players address a visible `{tenantId, worldSlug, realmSlug}` realm, never a raw `gameInstanceId`. Game Session persists `gameplay_admission_pointer` rows and append-only audit events. The current row always requires one positive runtime target and cannot yet express the target `CLOSED` state. `pointerVersion` tracks runtime-target changes while `catalogRevision` tracks catalog/policy changes; see the [Versioning & Runtime Configuration owner status](../../architecture/system-architecture-versioning-runtime.md#implementation-status) for the current persistence boundary and remaining cutover gaps.

Selectors resolve to a tenant-local durable `realmId` before direct pointer authority is read. The target canonical singular key is `{tenantId, realmId}`; `GetAdmissionPointer(tenantId, realmId)` reads direct pointer authority using that key and does not reconstruct authority through browse projection. The current Game Session proto and `GameplayAdmissionPointerAuthorityService` still use `{tenantId, worldSlug, realmSlug}` slug lookup; realm-ID lookup and caller support remain implementation drift and are not claimed as live. Target Account bootstrap admission, public-production membership creation, prepared cutover validation, live admission, and operator audit reads use the same resolved realm identity. Membership join and connect-token issuance have separate idempotency contracts: each binds its own `requestId` to its operation, caller, verified discovery scope, and resolved target digest, and the two request IDs are not interchangeable. The current persistence primitive checks the expected `{pointerVersion, catalogRevision}` under a row lock, conditionally updates an existing row against both prior values, and commits the pointer with its audit event in one transaction. This is owner-local persistence proof, not public mutation or full prepared-cutover support; see the [Versioning & Runtime Configuration owner status](../../architecture/system-architecture-versioning-runtime.md#implementation-status). V2 enforces tenant-local selector uniqueness, but persistence has not converged on canonical `{tenantId, realmId}` addressing or retained catalog-to-realm mapping.

Configured bootstrap pointer seeds are validated but not published automatically: startup creates no authority rows without World-owned lifecycle proof, and an empty store remains closed. `GameplayCatalogProperties` is not production routing authority: Game Session's production catalog projection is pointer-backed, Account Service no longer ships the old local catalog config, and property-to-catalog construction remains only in explicit test support. See the canonical [World Lifecycle and Admission Boundary](../../architecture/microservices/game-session-service/api-contracts.md#world-lifecycle-and-admission-boundary) and the [Game Session runtime tracker](./game-session-runtime-and-tick-coordination.md) for current implementation and proof status.

Game Session exposes canonical world, realm, and pointer reads plus pointer list, audit, runtime-state, prepared-upgrade, and cutover control-plane surfaces. The public selector-shaped singular helper and preferred runtime-target lookup have been removed; reverse runtime-target consumers use `listByRuntimeTarget(...)` so multiplicity is observable. Logging & Admin is an operator ingress over these contracts, not a second routing owner. Its audit route is `GET /admission-pointers/{tenantId}/{worldSlug}/{realmSlug}/audit`; authenticated tenant access is checked before the call, response tenant mismatches fail closed, and operator pointer mutation derives `actorPrincipal` from the authenticated session rather than caller input.

### Complete Authority and Ambiguity Rules

The shared `GameplayAdmissionPointerSnapshots` rule defines a complete pointer as one with positive `tenantId`, positive `gameInstanceId`, positive `pointerVersion`, nonblank `worldSlug`, `realmSlug`, and `stateScope`. Singular runtime-target authority exists only when the raw current-pointer result contains exactly one row and that row is complete. Any additional row, incomplete row, missing runtime identity, or missing scope makes the singular projection unavailable; incomplete rows are not discarded before multiplicity is assessed. Raw pointer lists still expose such rows for operator inspection.

`GameplayWorldCatalog` applies the shared completeness rule and additionally requires `characterCreationPolicy`. It groups rows by `{tenantId, worldSlug, realmSlug}` and emits a visible catalog entry only for exactly one complete row in that tenant-qualified selector scope. Reverse runtime-target lookup emits one visible identity only when exactly one realm survives for the tenant/runtime target; duplicate selector rows within a tenant, duplicate runtime matches, and incomplete rows disappear from player-facing catalog projection rather than selecting an arbitrary row.

The current local #2857 receiver correction keeps the catalog-side boundary fail-closed: current world/realm text presentation and selection use exact stable slugs only, including canonical numeric-only slugs, without advertising or interpreting unsupported menu positions; typed APIs likewise never index a fresh list, and composed `PLAY`/`WORLDS` decisions use one immutable catalog snapshot. Public/caller-free realm snapshots contain only public-production realms, private-only defaults are not inferred when ambiguous, and `GetAdmissionPointer` validates the selected slug tuple against one actual tenant pointer-list response. This does not wire in the separate exact-target direct-text UUID menu store or establish complete canonical `tenantSlug/worldSlug` support; authenticated private `REALMS` retention, protected receiving, explicit `JOIN`, and first-party admission remain gaps. R1430 passes 293 selected command/catalog/gRPC unit cases and 11 actual PostgreSQL migration cases, with no failures, errors or skips, plus canonical jOOQ generation and enabled service static/format checks. The initial migration test compilation failure was corrected before the separate physical run; the retained unit result and successful migration result are distinct runs. `AA-3.1`/`AA-3.3` remain partial and `drift-found` because the complete target is still absent. V1053 adds only a forward partial unique guard for visible public-production pointer cardinality per tenant; zero remains physically representable and is rejected by current readers, while the current realm catalog and V12/V13 are unchanged. The two new PostgreSQL cases prove successful existing-data migration, unchanged retained rows/events and migration history, rejection of duplicate visible public-production rows, and atomic refusal for pre-existing duplicate authority; nine existing pointer-migration cases also pass.

Admission-pointer `stateScope` is the canonical realm policy. Downstream `playableStateScope` is its resolved cross-service representation: `SHARED` maps to `PLAYABLE_STATE_SCOPE_SHARED` and `ISOLATED` maps to `PLAYABLE_STATE_SCOPE_ISOLATED`; it is not a second admission authority. If no single complete pointer can be proved, the singular downstream scope and routing bundle fail closed to unspecified/absent rather than reverse-inferring authority from `gameInstanceId`.

All routing-sensitive bundles preserve `tenantId`, `worldSlug`, `realmSlug`, resolved `gameInstanceId`, and `pointerVersion` together, with `characterSelection` and `playableStateScope` where applicable. Partial, blank, non-positive, stale, or selector-inconsistent bundles are not authoritative. At ingress, proxy and remote control-plane callers must provide `worldSlug`, `realmSlug`, and `pointerVersion` together or none; partial `ScheduleRemoteFollowup` input and partial remote coordinator/followup/result filters return `INVALID_ARGUMENT` instead of widening to an unscoped query. Persisted/read-model partial bundles collapse to absent rather than being projected as current identity.

### Admission, Membership, and Selection

Account-to-tenant membership is an explicit runtime substrate rather than an `accounts.tenant_id` shortcut. The live Account producer emits lifecycle and independent generation/version evidence, and current text `PLAY` consumes it with private-grant validation under the [canonical PLAY outcome matrix](../../architecture/system-architecture-authentication.md#play-current-and-target-failure-boundaries). Current connect-token issuance returns `AUTH_UNAVAILABLE` before cached replay or membership, entitlement, grant, and routing-authority reads. The Account-local explicit JOIN writer exists, while text JOIN dispatch remains unavailable. R1430 separately passes all 451 cases in the two selected Account service/RPC classes, including active, missing and inactive lifecycle/independent-generation producer mapping; these mocked cases do not prove full caller-target/atomic authority or connect-token enforcement. Current producer, writer and issuance details remain in [Account Runtime and Data](../../architecture/microservices/account-service/runtime-and-data.md); the target atomic authority and explicit join contract remains in [Authentication](../../architecture/system-architecture-authentication.md#in-band-play-admission-boundary).

Account bootstrap discovery has a supported HTTP character-roster capability, separate from unavailable direct-text `CHARS`; it does not establish gameplay admission. Current connect-token issuance is held before cached replay and fresh admission-authority processing. Its target persistence/replay and private-grant requirements remain owned by [Account Runtime and Data](../../architecture/microservices/account-service/runtime-and-data.md#connect-token-issuance-persistence-and-retention). Text `PLAY` retains its separate current private/playtest grant check. Neither a discovery snapshot nor a returning shortcut substitutes for complete current authority; invalid or expired scope requires fresh discovery rather than a cached target fallback.

The direct-text [REALMS-to-JOIN scope handoff](../../architecture/system-architecture-authentication.md#direct-text-realms-to-join-scope-normative) remains target/unimplemented because Account direct-text `JOIN` issuance/validation and Game Session transport-local scope retention through retry, terminal outcome, or expiry still lack implementation and focused proof. This is distinct from the browser/WebSocket bootstrap snapshot and remains a contract gap rather than current proof.

Gateway and Game Session preserve and validate `worldSlug`, `realmSlug`, `connectScopeId`, `connectRequestId`, `pointerVersion`, and resolved target in first-party connect context. The durable bootstrap shell stores the selector identity and is the reconnect/login/`PLAY` fallback when transient registry state is absent. Generic websocket bootstrap preserves an incoming complete bundle, repairs a runtime-only shell only from one complete current pointer, and collapses ambiguous or incomplete authority to no bundle. If a reused shell had a bundle and the repaired incoming shell does not, it is a real route change: the `BOOTSTRAP_ROUTE_CHANGED` path clears authenticated/gameplay state instead of preserving the older route.

### Session Freshness and Runtime Entry Points

`SessionAuthenticationService` is the canonical higher-level session reader. Tenant-aware `resolveUnverifiedSessionContext(...)` applies stale-pointer normalization; raw `findBySessionId(...)` is only an index for tenant discovery and cannot revive a missing `{tenantId, sessionId}` authority row. Session-id replay, logout, tick-state, failed-login cleanup, and websocket bootstrap reuse consume the canonical helpers. Credential `LOGIN` resolves its bootstrap runtime only from that normalized shell and returns `SESSION_NOT_FOUND` when no bootstrap target survives; it never treats the transport `sessionId` as a runtime id. Gameplay-identity and gameplay-name helpers are also centralized there for `PLAY` existing-binding reuse, durable replay fallback, communication availability, and recipient delivery.

Current normalization clears a stored gameplay binding when it no longer matches current pointer authority, keeps the account logged in, clears live gameplay presence, emits the stale-pointer/region-exit lifecycle effect, and makes later gameplay fail at `PLAY_REQUIRED`. This protects new `LOGIN`/`PLAY` and reconnect from stale routes but currently also invalidates an already connected source binding after cutover. The [Protocol Bridging](../../architecture/system-architecture-protocol-bridging.md) document is the canonical owner for entitlement-continuity and retained-edge policy. The current runtime has no recorded implementation or focused proof for that entitlement-continuity path.

Command staging chooses an admitted gameplay runtime first, then an explicit bootstrap runtime only when the shell retains a complete bootstrap routing bundle; otherwise it fails closed with `NOT_FOUND`. It never treats a numeric `sessionId` as a runtime target. Current runtime-target authority repairs stale command metadata only when one complete pointer proves the target. For an already selected gameplay scope, missing, ambiguous, or incomplete authority persists `playableStateScope=UNSPECIFIED` with no world/realm/version bundle. The current blank-scope login/bootstrap branch is a narrower exception: when runtime authority cannot be resolved, it preserves a normalized shell `{worldSlug, realmSlug, pointerVersion}` trio while persisting `playableStateScope=UNSPECIFIED`. This trio is a non-authoritative lobby selection hint, not an admitted routing bundle: it cannot establish or preserve a runtime route, authorize `PLAY`, or become downstream gameplay metadata. Complete pre-`PLAY` shell metadata is freshness-checked before persistence. Durable command execution and selected-work manifests normalize/collapse admitted routing metadata before replay or tick-batch sealing.

`QueryState(sessionId)` requires a normalized live session shell with positive tenant authority and never guesses a Redis key from a runtime id. Logout stops a runtime only when explicit scope or exactly one complete current isolated pointer positively proves that decision; missing, partial, or multiple pointers mean keep the runtime running. TCP Proxy disconnects suspend runtime state only with explicit `gameInstanceId`; advisory `sessionId` is never promoted, and missing runtime metadata remains best-effort session cleanup plus missing-context metering. Proxy producers and consumers preserve this envelope contract, and partial proxy routing headers are normalized to an unscoped bootstrap rather than forwarded as malformed authority. Authenticated TCP Proxy/Game Session callbacks and Game Session/Game Logic blocking clients use internal-service gRPC identity, with packaged-stack blocking stubs bound to the resolved customizer rather than a provider/no-op fallback.

### Durable Delegation and Control-Plane Projection

Game Session to Game Logic and Entity Management gameplay attestations carry `worldSlug`, `realmSlug`, `pointerVersion`, and `playableStateScope` as an all-or-none admitted claim; downstream guards reject partial claims. Gameplay-originated Automation ingress, timer and materialized schedule work, pin projections, script work/audit/handoff/dead-letter records, automation command handoff, and operator reads preserve the same bundle. Runtime-state projection also carries stored `runtimeRegionId` or `targetRegionId` hints where those consumers already own them, so region-aware plugin/policy preflight and handoff target reads do not collapse to game-instance-only lookup. Live and recent account/friend presence validates against singular current runtime authority; stale rows fall back to recent/offline projection rather than hiding a still-current session or inventing display metadata.

`GetGameInstanceRuntimeState` exposes `currentAdmissionPointers[]`. Its legacy singular `playableStateScope`, `worldSlug`, `realmSlug`, and `pointerVersion` fields are populated only for one complete current pointer; ambiguous or incomplete authority clears those fields while retaining the explicit list. Command-status and remote control-plane projections use the same rule and mark persisted routing stale when current singular authority cannot be proved. Logging & Admin exposes tenant-guarded `GET /admission-pointers/runtime-state/{tenantId}/{gameInstanceId}`, maps canonical runtime metadata, publication details, and current pointers, returns `404` for no runtime row, and rejects response-tenant mismatch as an internal contract failure.

Remote followup persistence and projection use one normalized `{playableStateScope, worldSlug, realmSlug, pointerVersion}` shape. Scope alone is not authoritative; partial stored rows, retry comparisons, coordinator/followup/result projections, and scheduling metadata collapse to no routing identity. The canonical scripting contract defines the remote-handoff outcome and audit vocabulary; this tracker records the local consequence that handoff success requires a non-error response with nonblank `coordinatorId` and `followupId`, while an invalid response becomes `DEAD_LETTERED` rather than `HANDED_OFF`. See the [normative scripting contract](../../architecture/system-architecture-scripting-normative-contract-tables.md#remote-follow-up-tuple-binding-normative).

### Realm-Scoped Playable State

Tenant membership and character ownership do not imply a shared gameplay namespace. Each realm carries explicit `stateScope` and `characterCreationPolicy`; shared-state realms use a tenant-live `playableStateKey`, while isolated realms, including playtest forks, use an instance-local key. The supported Account bootstrap/HTTP character roster is separate from direct-text `CHARS`, which currently returns unavailable without consulting Entity's legacy roster adapter. The accepted realm-local `CHARS` contract is defined by [ADR 0140](../../architecture/decisions/adr-0140-realm-authored-controllable-actor-entry.md); it is not proof of current text discovery. Isolated realms cannot read or mutate the tenant's production roster through tenant-wide or bare-character shortcuts.

For persistent/shared mutating smoke, this namespace boundary would be the mutation boundary, but the required restricted-synthetic verifier and proof remain unavailable. The bounded run-owned Compose mutation/teardown boundary is implemented, but persistent/shared identity/namespace/fence isolation remains unproved. Follow the [canonical testing owner](../../architecture/system-architecture-testing.md#player-flow-smoke-and-reset-boundaries) for the boundary contract.

Account identity and supported account-level cross-game character discovery remain distinct from the accepted target realm-local gameplay `CHARS` contract. The live `INVENTORY` surfaces are character gameplay inventory under the resolved playable-state namespace, not an Account-owned cross-game inventory; any future account inventory needs an explicit ownership and transfer contract rather than reuse of realm-local rows.

Entity Management is the target owner of shared `ScopedCharacterResolver` and `PlayableStateKeyResolver` boundaries and must echo the server-resolved target to callers; this tracker records that target intent, not completed convergence. Current Entity resolution still derives the legacy `playableStateKey` values `shared-live` or `instance:<gameInstanceId>`, while the live schema lacks stable `playableStateNamespaceId` columns for several durable state families and current REST/gRPC surfaces do not yet carry that stable namespace field uniformly. The target `{tenantId, playableStateNamespaceId, ...domainObjectId}` identity, namespace-qualified state APIs, and cross-playable-state rejection therefore remain partial and unproved; see the [Entity Management runtime/data owner status](../../architecture/microservices/entity-management-service/runtime-and-data.md#implementation-status).

The legacy Automation `PATCH /factions/{id}/reputation` controller has been removed, so that unauthenticated HTTP route fails closed. Automation's `faction_standing` storage and service remain, however, and are not Social owner-cutover proof. Standing migration, stable namespace identity, Social owner mutation/read APIs, consumer cutover, and focused proof remain open; see the [Social & Groups runtime/data owner contract](../../architecture/microservices/social-groups-service/runtime-and-data.md#data-model).

## Active Gaps

- The [protected installation registry prerequisite](#protected-installation-registry-prerequisite) still lacks a protected current-installation source; default and runtime registration remain denied, and all-owner epoch/applicability and FRESH manifest collection remain unavailable.
- Later gameplay-state families, especially loadouts, abilities, authored effects, richer resource tables, and any new character-creation or social/runtime consumer, still need explicit adoption of `{tenantId, gameInstanceId, playableStateScope}` before they become live. They must not reopen tenant-wide or bare-character shortcuts.
- Entity Management owns actor rows and the Account relationship/projection to those rows remains an evolving Account/Entity seam. Actor rows carry account and tenant identity, but neither membership nor that relationship establishes one implicit gameplay namespace across realms.
- Text `JOIN`/`Join & Play` dispatch remains unimplemented; the Account-local explicit writer is separate. Text `PLAY` lifecycle/generation validation is implemented; its outcome rules remain with the canonical owner linked above. Current connect-token issuance remains held before replay and authority reads. Full caller-target/atomic authority, connect-token membership/version reread, `allowNewGameplayBindings`, grant lifecycle/expiry, and lease-commit boundaries remain gaps; no membership is created implicitly.
- Future routing-sensitive delegated consumers, replay-sensitive caches, and new automation follow-up families need explicit proof that they preserve the complete bundle and fail closed; closed `09.1` seams do not imply unreviewed consumers are safe.
- Blank-scope login/bootstrap command staging currently retains the normalized shell selection hint with `playableStateScope=UNSPECIFIED` when runtime-target authority is absent, ambiguous, or incomplete. The implementation still needs focused proof that this hint cannot be consumed as routing authority or downstream gameplay metadata, plus convergence if any consumer crosses that boundary.
- Region-partitioned runtime ownership and broader region fencing are tracked separately from admission routing. Current runtime projections carry region hints where available but do not implement the final execution-partition topology.
- Replacement-instance migration/remap mechanics and domain-specific carry-forward rules remain unimplemented, including economy, guild, and combat-specific policy.
- The current pointer model cannot represent explicit `CLOSED`. Runtime-target changes advance `pointerVersion`; catalog/policy changes advance separate `catalogRevision`, so display and other catalog-only edits do not advance the runtime route version. Current active bindings are still fenced against current pointer state rather than ended through the target bounded drain.
- The target replacement cutover also requires one World-owned durable `cutoverHoldId`/`cutoverHoldFence` after target `ACTIVE` proof. The current implementation has no hold record or coordinated acquire/finalize/readback surface; it does not block source/target termination while the hold is unresolved, bind the hold into the pointer/audit/prepared-execution/source-cleanup/drain-fence transaction, or prove safe abort versus finalization. Expiry and contradictory evidence therefore have no implemented reconciliation proof.
- The internal authority locks an existing pointer row, requires the expected `pointerVersion` and `catalogRevision` pair, and issues the existing-row update with both prior values in the database predicate. This owner-local CAS does not enable control-plane mutation: the public mutation path remains fail-closed, and full prepared-cutover CAS/readback is unimplemented.
- The internal pointer authority commits pointer state and its audit event together. The `ExecutePreparedVersionCutover` RPC currently fails closed before authority/preparation reads or execution marking, so no live cutover writes prepared-execution state in that transaction. The full target atomic retry/reconciliation boundary, including prepared execution and hold/drain evidence, remains unimplemented; drain work, acknowledgement, and readback must each remain bound to the exact `sourceGameInstanceId` as well as `sourceDrainId`.
- Current storage uses the tenant-local selector key `(tenant_id, world_slug, realm_slug)` (V2) and separately persists globally unique `realm_id` values (V6). The target composite `{tenantId, realmId}` key/index is not yet the repository lookup or uniqueness key; canonical realm-ID addressing and retained catalog-to-realm mapping remain unimplemented.
- The canonical grant record permits expiry and calls for tenant-admin management; the registered legacy Account grant row and internal-only grant endpoints do not implement that follow-through. Unregistered lifecycle-bound storage retains expiry, request replay and tombstones; its read proof and remaining authorization and consumer gaps are tracked in [Player Access](./player-access-and-session.md#lifecycle-bound-private-realm-grant-source-preparation).
- The current documentation-only slice passed `./gradlew linkCheck lintMarkdown`. Validation and runtime-proof selection follows the [validation and runtime-proof workflow](../../developer-workflows/validation-and-runtime-proof.md); runtime proof is not applicable to this documentation-only checkpoint.

## To Discuss

No competing implementation is recorded for visible realm addressing, world-qualified admission-pointer authority, or shared-versus-isolated playable state. Design discussion is required before changing public admission policy, adding another isolated-state mode, defining replacement-instance migration/carry-forward rules, or introducing a gameplay-state family with different namespace semantics. The current open question is how future families and migration rules should preserve the established namespace and freshness fences without inventing a second authority model.
