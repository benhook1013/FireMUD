# Realm Routing and Playable State

## Target-State Authority

This is a non-normative implementation tracker for realm routing and playable state. Canonical target-state realm visibility, admission pointers, playable-state projection, runtime target identity, and freshness contracts remain authoritative in [design/architecture](../../architecture/README.md) and the linked design sources below; this tracker owns current implementation status, proof evidence, gaps, and handoffs, not normative design.

## Current Status

The realm-catalog projection, exact `WORLDS`/`REALMS` ordinal snapshots, persisted-pointer reads, bootstrap/connect-scope flow, session-freshness normalization, and local runtime projections are implemented; this does not establish complete routing or live admission. `WORLDS` and its ordinal snapshot share one catalog read. Game Session retains caller-bound Account scopes and JOIN request IDs in bounded shared Redis state keyed by the stable numeric transport session; it binds world and realm ordinals to their exact response snapshots through the shared `DirectTextOrdinalSelectionResolver`, and stale or changed numeric selectors fail closed. Current text `JOIN` accepts the retained `WORLDS` ordinal or a uniquely resolving bare world slug; the latter is implementation drift. The pointer has no `tenantSlug`, so stable `tenantSlug/worldSlug` selection remains unavailable. Authority-backed discovery suppresses cross-tenant case-insensitive slug collisions without collapsing tenant-bound ordinal choices. Scope and selector snapshots expire; per-key compare-and-set protects retry binding and replacement. The source-YAML initializer proof reads shipped application YAML directly and proves source-configuration binding only; it is not packaged-artifact, fresh-boot, persisted-seed, or live-admission proof. Focused unit proof exists; Docker-gated Redis cross-instance/retry proof was skipped locally. Full direct-text/Telnet and first-party `Join & Play` end-to-end proof, PostgreSQL lost-acknowledgement/concurrency proof, and complete pending-operation recovery remain open.

Account membership, entitlement, and grant readers fail closed before data access until typed caller/target binding is available, so there is no composed live admission proof; direct-text `CHARS` returns `CHARACTER_LIST_UNAVAILABLE` before Entity. `GetAdmissionPointer` preserves exactly-one-visible-public-production-realm cardinality from one authoritative snapshot; catalog-revision and pointer-read failures retain typed retryable unavailable outcomes instead of becoming missing selectors or generic failures. Duplicate public rows remain an activation/data-decision gap. The internal pointer authority locks an existing row, checks expected `pointerVersion` and `catalogRevision`, conditionally updates against both prior values, and commits pointer plus audit together. Public pointer mutation and cutover RPCs remain fail-closed; prepared-cutover execution, explicit `CLOSED`, complete revision-consumer convergence, canonical `{tenantId, realmId}` repository addressing and retained catalog mapping, hold/drain atomicity, and bounded active-session drain remain incomplete. Public/grant policy is also partial: lifecycle-bound grant expiry, monotonic mutation outcomes/tombstones, and tenant-admin management are absent; playtest initialization/reset, all-owner manifests, lifecycle generations, and close/expiry orchestration remain unimplemented or unproved. See [Authentication](../../architecture/system-architecture-authentication.md) and [Game Session protocols](../../architecture/microservices/game-session-service/protocols.md) for canonical contracts.

## Consolidated Implementation Record

### Authority and Pointer Contract

Players address a visible `{tenantId, worldSlug, realmSlug}` realm, never a raw `gameInstanceId`. Game Session persists `gameplay_admission_pointer` rows and append-only audit events. The current row always requires one positive runtime target and cannot yet express the target `CLOSED` state. `pointerVersion` tracks runtime-target changes while `catalogRevision` tracks catalog/policy changes; see the [Versioning & Runtime Configuration owner status](../../architecture/system-architecture-versioning-runtime.md#implementation-status) for the current persistence boundary and remaining cutover gaps. Complete all-consumer convergence and exact retained-audit proof remain open; unknown historical identity/revision is not backfilled.

Selectors resolve to a tenant-local durable `realmId` before direct pointer authority is read. The target canonical singular key is `{tenantId, realmId}`; target `GetAdmissionPointer(tenantId, realmId)` reads direct authority rather than reconstructing it through a browse projection. The current Game Session proto and `GameplayAdmissionPointerAuthorityService` still use `{tenantId, worldSlug, realmSlug}` slug lookup; realm-ID lookup and caller support are not live. Target Account bootstrap admission, public-production membership creation, prepared-cutover validation, live admission, and operator audit reads use the same resolved realm identity. Membership join and connect-token issuance have separate idempotency contracts: each binds its own `requestId` to its operation, caller, verified discovery scope, and resolved target digest, and the IDs are not interchangeable. Current pointer persistence locks an existing row, compares both expected `{pointerVersion, catalogRevision}` values, conditionally updates against both prior values, and commits pointer and audit in one transaction. This owner-local persistence boundary does not provide public mutation or full prepared-cutover support; PostgreSQL concurrency/lost-acknowledgement proof remains open when Docker-gated runs skip. V2 enforces tenant-local selector uniqueness, but canonical `{tenantId, realmId}` repository addressing and retained catalog-to-realm mapping remain incomplete.

Configured bootstrap pointer seeds are validated but not published automatically: startup creates no authority rows without World-owned lifecycle proof, and an empty store remains closed. `GameplayCatalogProperties` is not production routing authority: Game Session's production catalog projection is pointer-backed, Account Service no longer ships the old local catalog config, and property-to-catalog construction remains only in explicit test support. See the canonical [World Lifecycle and Admission Boundary](../../architecture/microservices/game-session-service/api-contracts.md#world-lifecycle-and-admission-boundary) and the [Game Session runtime tracker](./game-session-runtime-and-tick-coordination.md) for current implementation and proof status.

Game Session exposes canonical world, realm, and pointer reads plus pointer list, audit, runtime-state, prepared-upgrade, and cutover control-plane surfaces. The public selector-shaped singular helper and preferred runtime-target lookup have been removed; reverse runtime-target consumers use `listByRuntimeTarget(...)` so multiplicity is observable. Logging & Admin is an operator ingress over these contracts, not a second routing owner. Its audit route is `GET /admission-pointers/{tenantId}/{worldSlug}/{realmSlug}/audit`; authenticated tenant access is checked before the call, response tenant mismatches fail closed, and operator pointer mutation derives `actorPrincipal` from the authenticated session rather than caller input.

### Complete Authority and Ambiguity Rules

The shared `GameplayAdmissionPointerSnapshots` rule defines a complete pointer as one with positive `tenantId`, positive `gameInstanceId`, positive `pointerVersion`, nonblank `worldSlug`, `realmSlug`, and `stateScope`. Singular runtime-target authority exists only when the raw current-pointer result contains exactly one row and that row is complete. Any additional row, incomplete row, missing runtime identity, or missing scope makes the singular projection unavailable; incomplete rows are not discarded before multiplicity is assessed. Raw pointer lists still expose such rows for operator inspection.

`GameplayWorldCatalog` applies the shared completeness rule and additionally requires `characterCreationPolicy`. V2 enforces tenant-qualified pointer uniqueness. The current player-facing catalog suppresses complete pointers with a cross-tenant case-insensitive world-slug collision before grouping and refuses ambiguous bare-slug resolution, so it cannot merge two tenants into one displayed world; text browse currently exposes public-production realms only, pending typed Account grant evidence for private discovery; WORLDS and its ordinal targets share one catalog read; numeric selection binds to that response-local snapshot, catalog revision, and target/catalog fingerprints, rejecting stale or reordered values instead of reindexing them. Focused local unit proof covers this bounded snapshot behavior. The full live direct-text/Telnet path remains unproved; the stable tenant-qualified selector remains unavailable until the pointer carries `tenantSlug`. Reverse runtime-target lookup emits one visible identity only when exactly one realm survives for the tenant/runtime target. Incomplete pointer rows are excluded from the player-facing projection; stable tenant-qualified discovery is a distinct remaining capability gap.

Admission-pointer `stateScope` is the canonical realm policy. Downstream `playableStateScope` is its resolved cross-service representation: `SHARED` maps to `PLAYABLE_STATE_SCOPE_SHARED` and `ISOLATED` maps to `PLAYABLE_STATE_SCOPE_ISOLATED`; it is not a second admission authority. If no single complete pointer can be proved, the singular downstream scope and routing bundle fail closed to unspecified/absent rather than reverse-inferring authority from `gameInstanceId`.

All routing-sensitive bundles preserve `tenantId`, `worldSlug`, `realmSlug`, resolved `gameInstanceId`, and `pointerVersion` together, with `characterSelection` and `playableStateScope` where applicable. Partial, blank, non-positive, stale, or selector-inconsistent bundles are not authoritative. At ingress, proxy and remote control-plane callers must provide `worldSlug`, `realmSlug`, and `pointerVersion` together or none; partial `ScheduleRemoteFollowup` input and partial remote coordinator/followup/result filters return `INVALID_ARGUMENT` instead of widening to an unscoped query. Persisted/read-model partial bundles collapse to absent rather than being projected as current identity.

### Admission, Membership, and Selection

Account-to-tenant membership is an explicit runtime substrate rather than an `accounts.tenant_id` shortcut, and the public default production realm is the only v1 open-enrollment path. The obsolete implicit writer is removed; Account's `JoinPublicProductionMembership` writer is implemented locally with lifecycle-aware fields, policy-bound idempotency, and the membership/audit outbox transaction. Current Account membership reads and text-client `PLAY` carry `membershipExists`, `membershipLifecycleState`, `gameplayAdmissionAllowed`, `membershipVersion`, `membershipAuthorityGeneration`, and `evaluatedAt`. On supplied-authority branches, `PLAY` admits only an exact safe `ACTIVE` snapshot; actionable public `JOIN_REQUIRED` requires a fresh Account response matching the exact account/tenant, validated lifecycle/version/generation/evaluation time, and either missing (`MISSING`) or existing `INACTIVE` membership, plus fresh entitlement confirming gameplay availability and `allowPublicJoin`. Other non-admitting states are denied. The current proto represents `membershipAuthorityGeneration` as `uint64` and `PLAY` requires positivity; this is implementation drift from the target opaque, exact-equality-only generation semantics. Live Account membership, entitlement, and grant handlers validate the trusted peer then return in-band `FAILED_PRECONDITION` before reads, so local classifications do not establish composed public `PLAY` or live `JOIN_REQUIRED`; text `PLAY` classifies the membership response as `WORLD_ACCESS_DENIED`, while AccountClient separately normalizes transport-level `StatusRuntimeException` to retryable `AUTH_UNAVAILABLE`. For non-public realms, current connect-token issuance maps missing membership to `NON_PUBLIC_ENROLLMENT_REQUIRED` and existing non-admitting membership to `CONNECT_TOKEN_REJECTED`; text `PLAY` maps either case to `WORLD_ACCESS_DENIED` before grant lookup. Supplied-authority text `PLAY` then performs the Account-owned grant check, and a grant never substitutes for membership. Game Session's direct-text `JOIN` retrieves retained REALMS scope/request state and invokes the Account writer locally; this does not establish complete direct-text/Telnet or first-party `Join & Play` proof. The target membership-authority-generation reread and applicable realm-grant validation at connect-token issuance remain gaps. Public-production classification remains explicit pointer/catalog metadata, not `realmSlug == "production"`; canonical admission behavior and status remain owned by [Authentication](../../architecture/system-architecture-authentication.md#implementation-status).

First-party bootstrap discovery exposes worlds, realms, and characters as the same catalog/admission projection used by `WORLDS`, `REALMS`, `CHARS`, and `PLAY`. Discovery returns opaque, short-lived `connectScopeId` plus `pointerVersion`, `evaluatedAt`, and `connectScopeExpiresAt`. The Game Session text `PLAY` grant branch has local response-classification coverage, but the live Account membership handler rejects before that branch is reached. Current `/auth/connect-token` issuance revalidates current pointer/visibility and membership but does not validate the applicable grant. The current path uses a bounded Redis replay map containing the raw token or a deterministic failure, and it may read that map before a fresh entitlement/membership reread. Its read-then-mint and unconditional-write sequence is non-atomic: concurrent identical live requests can mint different raw tokens with the same deterministic `jti` before one overwrites the replay entry, so exact same-result replay remains target behavior and is not proved. See [Account Runtime and Data](../../architecture/microservices/account-service/runtime-and-data.md#connect-token-issuance-persistence-and-retention) for the canonical current-versus-target persistence contract. Target issuance adds that fresh grant check and target replay gate. The target returning shortcut has the same grant gate, while the current shortcut and any resulting token are not authorization proof. Invalid scopes return `CONNECT_SCOPE_INVALID`; expired or cutover-mismatched scopes return `CONNECT_SCOPE_MISMATCH`, both directing the client to rerun discovery instead of using local target fallback.

The direct-text [REALMS-to-JOIN scope handoff](../../architecture/system-architecture-authentication.md#direct-text-realms-to-join-scope-normative) now retains the Account-issued scope and generated JOIN request ID in the shared Redis lobby record for the stable numeric transport session, with bounded scope expiry and atomic retry binding. `WORLDS` ordinal targets are persisted from the same catalog read as the response, and reordered or changed catalogs reject stale numeric selection rather than reindexing it; the current bare-world-slug selection re-resolves current authority only when unique in the catalog. Canonical tenant-scoped stable selector resolution remains a separate gap. Game Session consumes that retained scope/request pair and invokes Account's `JoinPublicProductionMembership` writer. Focused unit tests cover these local boundaries. The Docker-gated Redis integration proof is locally skipped without Docker, and the full direct-text/Telnet end-to-end path, first-party browser/WebSocket `Join & Play` path, terminal-outcome recovery, and direct text-to-Logging proof remain unproved. Account's bounded readback-only worker for abandoned JOIN `PENDING` intents is implemented, but PostgreSQL execution, lost-acknowledgement/concurrency proof, and complete pending-operation recovery/reconciliation remain open. This is distinct from the browser/WebSocket bootstrap snapshot.

Gateway and Game Session preserve and validate `worldSlug`, `realmSlug`, `connectScopeId`, `connectRequestId`, `pointerVersion`, and resolved target in first-party connect context. The durable bootstrap shell stores the selector identity and is the reconnect/login/`PLAY` fallback when transient registry state is absent. Generic websocket bootstrap preserves an incoming complete bundle, repairs a runtime-only shell only from one complete current pointer, and collapses ambiguous or incomplete authority to no bundle. If a reused shell had a bundle and the repaired incoming shell does not, it is a real route change: the `BOOTSTRAP_ROUTE_CHANGED` path clears authenticated/gameplay state instead of preserving the older route.

### Session Freshness and Runtime Entry Points

`SessionAuthenticationService` is the canonical higher-level session reader. Tenant-aware `resolveUnverifiedSessionContext(...)` applies stale-pointer normalization; raw `findBySessionId(...)` is only an index for tenant discovery and cannot revive a missing `{tenantId, sessionId}` authority row. Session-id replay, logout, tick-state, failed-login cleanup, and websocket bootstrap reuse consume the canonical helpers. Credential `LOGIN` resolves its bootstrap runtime only from that normalized shell and returns `SESSION_NOT_FOUND` when no bootstrap target survives; it never treats the transport `sessionId` as a runtime id. Gameplay-identity and gameplay-name helpers are also centralized there for `PLAY` existing-binding reuse, durable replay fallback, communication availability, and recipient delivery.

Current normalization clears a stored gameplay binding when it no longer matches current pointer authority, keeps the account logged in, clears live gameplay presence, emits the stale-pointer/region-exit lifecycle effect, and makes later gameplay fail at `PLAY_REQUIRED`. This protects new `LOGIN`/`PLAY` and reconnect from stale routes but currently also invalidates an already connected source binding after cutover. The [Protocol Bridging](../../architecture/system-architecture-protocol-bridging.md) document is the canonical owner for entitlement-continuity and retained-edge policy. The current runtime has no recorded implementation or focused proof for that entitlement-continuity path.

Command staging chooses an admitted gameplay runtime first, then an explicit bootstrap runtime only when the shell retains a complete bootstrap routing bundle; otherwise it fails closed with `NOT_FOUND`. It never treats a numeric `sessionId` as a runtime target. Current runtime-target authority repairs stale command metadata only when one complete pointer proves the target. For an already selected gameplay scope, missing, ambiguous, or incomplete authority persists `playableStateScope=UNSPECIFIED` with no world/realm/version bundle. The current blank-scope login/bootstrap branch is a narrower exception: when runtime authority cannot be resolved, it preserves a normalized shell `{worldSlug, realmSlug, pointerVersion}` trio while persisting `playableStateScope=UNSPECIFIED`. This trio is a non-authoritative lobby selection hint, not an admitted routing bundle: it cannot establish or preserve a runtime route, authorize `PLAY`, or become downstream gameplay metadata. Complete pre-`PLAY` shell metadata is freshness-checked before persistence. Durable command execution and selected-work manifests normalize/collapse admitted routing metadata before replay or tick-batch sealing.

`QueryState(sessionId)` requires a normalized live session shell with positive tenant authority and never guesses a Redis key from a runtime id. Logout stops a runtime only when explicit scope or exactly one complete current isolated pointer positively proves that decision; missing, partial, or multiple pointers mean keep the runtime running. `NotifyDisconnect` is advisory, read-only handling: Game Session deduplicates proxy event keys, meters duplicate or missing-context events, and validates an explicit `{tenantId, gameInstanceId}` against its `GameInstance`; it does not suspend runtime state or clean up sessions, and advisory `sessionId` is never promoted to runtime authority. Proxy producers and consumers preserve this envelope contract, and partial proxy routing headers are normalized to an unscoped bootstrap rather than forwarded as malformed authority. Authenticated TCP Proxy/Game Session callbacks and Game Session/Game Logic blocking clients use internal-service gRPC identity, with packaged-stack blocking stubs bound to the resolved customizer rather than a provider/no-op fallback.

### Durable Delegation and Control-Plane Projection

Game Session to Game Logic and Entity Management gameplay attestations carry `worldSlug`, `realmSlug`, `pointerVersion`, and `playableStateScope` as an all-or-none admitted claim; downstream guards reject partial claims. Gameplay-originated Automation ingress, timer and materialized schedule work, pin projections, script work/audit/handoff/dead-letter records, automation command handoff, and operator reads preserve the same bundle. Runtime-state projection also carries stored `runtimeRegionId` or `targetRegionId` hints where those consumers already own them, so region-aware plugin/policy preflight and handoff target reads do not collapse to game-instance-only lookup. Live and recent account/friend presence validates against singular current runtime authority; stale rows fall back to recent/offline projection rather than hiding a still-current session or inventing display metadata.

`GetGameInstanceRuntimeState` exposes `currentAdmissionPointers[]`. Its legacy singular `playableStateScope`, `worldSlug`, `realmSlug`, and `pointerVersion` fields are populated only for one complete current pointer; ambiguous or incomplete authority clears those fields while retaining the explicit list. Command-status and remote control-plane projections use the same rule and mark persisted routing stale when current singular authority cannot be proved. Logging & Admin exposes tenant-guarded `GET /admission-pointers/runtime-state/{tenantId}/{gameInstanceId}`, maps canonical runtime metadata, publication details, and current pointers, returns `404` for no runtime row, and rejects response-tenant mismatch as an internal contract failure.

Remote followup persistence and projection use one normalized `{playableStateScope, worldSlug, realmSlug, pointerVersion}` shape. Scope alone is not authoritative; partial stored rows, retry comparisons, coordinator/followup/result projections, and scheduling metadata collapse to no routing identity. The canonical scripting contract defines the remote-handoff outcome and audit vocabulary; this tracker records the local consequence that handoff success requires a non-error response with nonblank `coordinatorId` and `followupId`, while an invalid response becomes `DEAD_LETTERED` rather than `HANDED_OFF`. See the [normative scripting contract](../../architecture/system-architecture-scripting-normative-contract-tables.md#remote-follow-up-tuple-binding-normative).

### Realm-Scoped Playable State

Tenant membership and character ownership do not imply a shared gameplay namespace. Each realm carries explicit `stateScope` and `characterCreationPolicy`; shared-state realms use a tenant-live `playableStateKey`, while isolated realms, including playtest forks, use an instance-local key. `CHARS` is a realm-local roster with explicit creation policy. The scope-aware roster contract is used by bootstrap character discovery, `REALMS`, `CHARS`, `PLAY`, and `TELL`; isolated realms cannot read or mutate the tenant's production roster through tenant-wide or bare-character shortcuts.

For persistent/shared mutating smoke, this namespace boundary would be the mutation boundary, but the required restricted-synthetic verifier and proof remain unavailable. The bounded run-owned Compose mutation/teardown boundary is implemented, but persistent/shared identity/namespace/fence isolation remains unproved. Follow the [canonical testing owner](../../architecture/system-architecture-testing.md#player-flow-smoke-and-reset-boundaries) for the boundary contract.

Account identity and account-level cross-game character discovery remain distinct from realm-local gameplay `CHARS`. The live `INVENTORY` surfaces are character gameplay inventory under the resolved playable-state namespace, not an Account-owned cross-game inventory; any future account inventory needs an explicit ownership and transfer contract rather than reuse of realm-local rows.

Entity Management is the target owner of shared `ScopedCharacterResolver` and `PlayableStateKeyResolver` boundaries and must echo the server-resolved target to callers; this tracker records that target intent, not completed convergence. Current Entity resolution still derives the legacy `playableStateKey` values `shared-live` or `instance:<gameInstanceId>`, while the live schema lacks stable `playableStateNamespaceId` columns for several durable state families and current REST/gRPC surfaces do not yet carry that stable namespace field uniformly. The target `{tenantId, playableStateNamespaceId, ...domainObjectId}` identity, namespace-qualified state APIs, and cross-playable-state rejection therefore remain partial and unproved; see the [Entity Management runtime/data owner status](../../architecture/microservices/entity-management-service/runtime-and-data.md#implementation-status).

The legacy Automation `PATCH /factions/{id}/reputation` controller has been removed, so that unauthenticated HTTP route fails closed. Automation's `faction_standing` storage and service remain, however, and are not Social owner-cutover proof. Standing migration, stable namespace identity, Social owner mutation/read APIs, consumer cutover, and focused proof remain open; see the [Social & Groups runtime/data owner contract](../../architecture/microservices/social-groups-service/runtime-and-data.md#data-model).

## Active Gaps

- Later gameplay-state families, especially loadouts, abilities, authored effects, richer resource tables, and any new character-creation or social/runtime consumer, still need explicit adoption of `{tenantId, gameInstanceId, playableStateScope}` before they become live. They must not reopen tenant-wide or bare-character shortcuts.
- Entity Management owns actor rows and the Account relationship/projection to those rows remains an evolving Account/Entity seam. Actor rows carry account and tenant identity, but neither membership nor that relationship establishes one implicit gameplay namespace across realms.
- The Account `JoinPublicProductionMembership` writer and Game Session direct-text invocation are implemented locally: the retained REALMS scope/request pair reaches Account, which creates or restores `ACTIVE` membership with lifecycle, version, and authority-generation evidence and records the JOIN outcome/audit evidence transactionally. This does not prove the complete first-party `Join & Play` or direct-text/Telnet flow. Account's bounded readback-only worker revisits abandoned JOIN `PENDING` intents, but PostgreSQL execution, lost-acknowledgement/concurrency proof, and recovery/reconciliation after an unknown JOIN database outcome remain open. Current connect-token issuance and `PLAY` never create or restore membership; issuance still lacks the target fresh membership-authority-generation/version reread and applicable private/playtest grant validation. Local `PLAY` response-classification tests use supplied authority and do not establish a live membership snapshot: Account runtime membership, entitlement, and grant handlers return in-band `FAILED_PRECONDITION` before data reads, which text `PLAY` classifies as `WORLD_ACCESS_DENIED`; AccountClient separately normalizes transport-level `StatusRuntimeException` to retryable `AUTH_UNAVAILABLE`. Focused direct text-to-Logging end-to-end proof remains open.
- Future routing-sensitive delegated consumers, replay-sensitive caches, and new automation follow-up families need explicit proof that they preserve the complete bundle and fail closed; closed `09.1` seams do not imply unreviewed consumers are safe.
- Blank-scope login/bootstrap command staging currently retains the normalized shell selection hint with `playableStateScope=UNSPECIFIED` when runtime-target authority is absent, ambiguous, or incomplete. The implementation still needs focused proof that this hint cannot be consumed as routing authority or downstream gameplay metadata, plus convergence if any consumer crosses that boundary.
- Region-partitioned runtime ownership and broader region fencing are tracked separately from admission routing. Current runtime projections carry region hints where available but do not implement the final execution-partition topology.
- Replacement-instance migration/remap mechanics and domain-specific carry-forward rules remain unimplemented, including economy, guild, and combat-specific policy.
- The current pointer model cannot represent explicit `CLOSED`. Runtime-target changes advance `pointerVersion`; catalog/policy changes advance separate `catalogRevision`, so display and other catalog-only edits do not advance the runtime route version. Current active bindings are still fenced against current pointer state rather than ended through the target bounded drain.
- The target replacement cutover also requires one World-owned durable `cutoverHoldId`/`cutoverHoldFence` after target `ACTIVE` proof. The current implementation has no hold record or coordinated acquire/finalize/readback surface; it does not block source/target termination while the hold is unresolved, bind the hold into the pointer/audit/prepared-execution/source-cleanup/drain-fence transaction, or prove safe abort versus finalization. Expiry and contradictory evidence therefore have no implemented reconciliation proof.
- The internal authority locks an existing pointer row, requires the expected `{pointerVersion, catalogRevision}` pair, and issues the existing-row update with both prior values in the database predicate. This owner-local CAS does not enable public control-plane mutation, whose path remains fail-closed; full prepared-cutover CAS/readback is unimplemented.
- The internal pointer authority commits pointer state and its audit event together. `ExecutePreparedVersionCutover` currently fails closed before authority/preparation reads or execution marking, so it does not write prepared-execution state after the pointer transaction. Full target atomic retry/reconciliation, including prepared execution and hold/drain evidence, remains unimplemented; drain work, acknowledgement, and readback must each remain bound to the exact `sourceGameInstanceId` as well as `sourceDrainId`.
- V2 makes the pointer selector tenant-local by `(tenant_id, world_slug, realm_slug)`, and V6 separately persists globally unique `realm_id` values; the target `{tenantId, realmId}` key is not yet the repository lookup or uniqueness key. Migration order is V7 audit, V8 parent legacy-bootstrap repair, V9 parent admission-bind owner ledger, V10 parent run-owned launch identity, V11 visible public-production cardinality guard, and V12 audit-event tenant lookup index. V11/V12 preserve the child SQL bytes. Existing duplicate visible-public rows fail migration rather than choosing or deleting a survivor; focused local cardinality proof does not claim PostgreSQL/concurrency when Docker-gated runs skip. Any retained history recording the former child assignments (V7/V8/V9 cardinality or V9/V10 lookup) stays activation-blocked until exact Flyway-history and data readback plus owner disposition; do not manually repair data, run Flyway repair, rewrite history, enable out-of-order, or assume a no-data boundary.
- The canonical grant record permits expiry and calls for tenant-admin management; the current Account grant row and internal-only grant endpoints do not implement that follow-through.
- An earlier documentation-only checkpoint passed `./gradlew linkCheck lintMarkdown`. The current admission-pointer and JOIN work changes runtime code, schema, fixtures, and tests; focused local checks and the hosted PostgreSQL pointer-cardinality/WebSocket results are recorded with #2857, while retained-data deployment readback, live admission/reconnect, and aggregate CI remain open. Validation and runtime-proof selection follows the [validation and runtime-proof workflow](../../developer-workflows/validation-and-runtime-proof.md).

## To Discuss

No competing implementation is recorded for visible realm addressing, world-qualified admission-pointer authority, or shared-versus-isolated playable state. Design discussion is required before changing public admission policy, adding another isolated-state mode, defining replacement-instance migration/carry-forward rules, or introducing a gameplay-state family with different namespace semantics. The current open question is how future families and migration rules should preserve the established namespace and freshness fences without inventing a second authority model.
