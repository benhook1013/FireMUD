# Player Experience, Commands, and Communication

## Target-State Authority

This is a non-normative implementation tracker for player-facing commands, communication, presence, and client behavior. Canonical target-state player-experience and cross-service contracts remain authoritative in [design/architecture](../../architecture/README.md) and the linked design sources below; this tracker owns current capability status, proof evidence, gaps, and handoffs, not normative design.

## Current Status

This tracker is the permanent reader-facing implementation record for player-facing commands, admission, presentation, communication, presence, and client behavior. Most bounded capabilities are live, including the stored game-authored HELP path; broader command interpretation, rich help authoring/discovery, elevated staff behavior, richer communication, and the independently released static frontend artifact/host boundary remain explicitly incomplete. The Vite frontend build now emits compiled assets under the reserved `frontend-assets` directory, but independently released hosting and browser proof remain absent. The output/reconnect lane remains partial where explicit structured schema versioning, strict complete-byte context bounds, first-party post-logout suppression, and broader client consumption are not yet proven. Deliberate-`LOGOUT` replay suppression remains an unimplemented blocker requiring focused `LOGOUT` → `LOGIN` → `PLAY` proof that no private context is replayed; this tracker does not claim the runtime fix.

Packet 5 moderation/communication/social provenance is represented by [ADR 0146](../../architecture/decisions/adr-0146-owner-local-moderation-enforcement.md), [ADR 0147](../../architecture/decisions/adr-0147-explicit-communication-classes-and-owner-delivery.md), [ADR 0148](../../architecture/decisions/adr-0148-social-relationship-authority-and-entity-owned-value.md), [ADR 0149](../../architecture/decisions/adr-0149-communication-type-specific-history-and-retention.md), and [ADR 0150](../../architecture/decisions/adr-0150-closed-observer-views-and-profile-scoped-shout.md); Packet 6 P0 shared consequences are represented by [ADR 0151](../../architecture/decisions/adr-0151-event-scoped-automated-tier-a-credential-compliance.md), [ADR 0152](../../architecture/decisions/adr-0152-phased-environment-bound-deployment-preflight-and-expected-bindings.md), [ADR 0153](../../architecture/decisions/adr-0153-measured-online-backup-rpo-and-future-pitr-trigger.md), [ADR 0154](../../architecture/decisions/adr-0154-automated-recovery-proof-and-differentiated-traffic-open-gates.md), [ADR 0155](../../architecture/decisions/adr-0155-automated-event-classified-post-restore-trust-reset.md), [ADR 0156](../../architecture/decisions/adr-0156-risk-tiered-progressive-rollout-with-compatibility-bounded-rollback.md), [ADR 0157](../../architecture/decisions/adr-0157-dependency-classified-liveness-readiness-and-route-admission.md), [ADR 0158](../../architecture/decisions/adr-0158-simplified-observability-degradation-without-fallback-alert-authority.md), and [ADR 0159](../../architecture/decisions/adr-0159-profile-dependent-independent-deadman-and-public-path-monitoring.md) where player-facing delivery, history, or privacy boundaries are affected. These links do not upgrade any implementation or verification state.

## Current Gaps

- Gameplay presence role classification still maps global `platformAdmin` and legacy global `god` into in-game `ADMIN` and `GOD`; reconcile this against [ADR 0026](../../architecture/decisions/adr-0026-global-roles-do-not-grant-gameplay-authority.md).
- Profile-policy surfaces still accept `HIDDEN_STAFF` and fail closed to `PRIVATE` during projection; reconcile the vocabulary against [ADR 0046](../../architecture/decisions/adr-0046-bounded-friend-presence-with-private-by-failure-redaction.md).
- Player-facing presence responses still expose disconnect disposition; reconcile the response shape against [ADR 0046](../../architecture/decisions/adr-0046-bounded-friend-presence-with-private-by-failure-redaction.md).

## Canonical Design Sources

- [Player command model](../../architecture/system-architecture-player-command-model.md) defines command interpretation, stage behavior, typed metadata, and dispatch policy.
- [Input, output, and presentation](../../architecture/system-architecture-input-output-and-presentation.md) defines structured output, rendering, replay, prompts, localization, and protocol framing.
- [Settings model](../../architecture/system-architecture-settings-model.md) defines layered operator and tenant/game ownership, precedence, and effective-settings readback.
- [Authentication and authorization](../../architecture/system-architecture-authentication.md) defines gameplay presence, privacy, elevated actor policy, and admission stages.
- [Reconnection](../../architecture/system-architecture-reconnection.md) defines bounded semantic recent context and fresh redraw behavior without client-input or transport replay.

[ADR 0112](../../architecture/decisions/adr-0112-typed-bounded-gameplay-effect-extension.md) is the target link for release-pinned typed command effects and shared admission/mutation ownership; the current `EA-1.1` partial state and existing parser/registry proof do not establish general effect-plan execution. ## Consolidated Implementation Record

This section records implementation and proof status only. The target command, presentation, reconnection, settings, presence, privacy, and frontend contracts remain in the canonical sources listed above, including [ADR 0026](../../architecture/decisions/adr-0026-global-roles-do-not-grant-gameplay-authority.md) and [ADR 0046](../../architecture/decisions/adr-0046-bounded-friend-presence-with-private-by-failure-redaction.md).

### Admission, Commands, and Capabilities

Current text behavior exposes `WORLDS` as an optional pre-login public browse, then `LOGIN` followed by `PLAY <world> [character]` as the direct gameplay-binding path for existing members. Realm and character discovery helpers are currently not required ceremony. Text `PLAY` and connect-token issuance return `JOIN_REQUIRED` only when fresh authority confirms a publicly visible target with an allowed public-production join policy and the caller's membership is absent; policy denial remains `PUBLIC_PRODUCTION_ADMISSION_DENIED`, while unavailable or invalid authority remains the applicable unavailable/invalid-authority outcome. An unambiguous eligible `PLAY` enters directly; ambiguous or inaccessible selections return selection-oriented or explicit bounded errors rather than low-level gameplay failures. Wrong-stage input produces guidance such as `LOGIN_REQUIRED` or `PLAY_REQUIRED`.

The current admission gaps are explicit `JOIN`, realm-scoped discovery/character ceremony, and the connect-token membership-authority-generation reread. The `PLAY`-side `JOIN_REQUIRED` behavior and connect-token missing-membership rejection are implemented; canonical admission behavior remains in [Authentication and authorization](../../architecture/system-architecture-authentication.md) and [ADR 0025](../../architecture/decisions/adr-0025-explicit-open-enrollment-membership.md).

### HELP, Settings, and Presentation

- Current behavior: built-in `HELP` is filtered by effective optional command capability. A bounded game-authored topic path supports tenant/template-scoped published topics, normalized exact lookup, and platform fallback. `FEATURE_UNAVAILABLE` is returned for disabled direct optional commands. Communication, prompt, presentation, and reconnect settings have typed metadata and effective-settings readback across their owning services.
- Current proof and gap: parser, registry, capability, HELP/history, rendering, prompt, WebSocket/Telnet parity, and settings tests cover these seams. Rich authoring UI, localization-aware help, fuzzy/semantic search, related-topic and stage-aware discovery, richer prompt composition, and broader smart-client presentation remain incomplete.
- Current behavior: `PlayerOutput` remains structured until rendering; Telnet and generic WebSocket receive renderer-owned text, while first-party WebSocket responses and recipient pushes use structured envelopes. `LOOK`, movement refresh, communication, prompt, and reconnect paths use typed output metadata. The current `web-client` only generically JSON-parses the WebSocket envelope as `unknown`, so semantic structured `PlayerOutput` consumption and compatibility proof remain absent. Fresh room reads are authoritative and prompts are excluded from replay; schema/projection contract status is linked in [Input, Output, and Presentation](../../architecture/system-architecture-input-output-and-presentation.md).

### Transcript, History, and Room Views

- Current behavior: durable semantic recent-context rows are the bounded source of recent output and Redis is a best-effort hot cache. Structured entries preserve identity, ordering, payload metadata, and compatibility text. `HISTORY` is a separate accepted-command store. `LOGOUT` clears live presence and reconnect eligibility in storage, but the first-party connect-context replay handler currently ignores that eligibility and may replay retained rows; durable retained rows are distinct from reconnect eligibility. Complete-entry byte bounds and omission behavior remain implementation/proof gaps tracked by [Reconnection](../../architecture/system-architecture-reconnection.md) and [ADR 0134](../../architecture/decisions/adr-0134-bounded-durable-semantic-reconnect-context.md).
- Current proof and gap: focused transcript, repository-ordering, retention, Redis, settings, and HISTORY tests cover the storage boundary. The handler-side eligibility check owns the post-logout suppression fix; post-logout first-party replay still contradicts canonical termination behavior, and full transcript archive/export, raw transport-byte replay, and player-controlled history export remain incomplete.
- Current behavior: Game Logic composes ordinary floor-free `LookResult` data from World Management and Entity Management; Game Session enforces access and renders the result. Current request/proto evidence carries no causal-fence evidence, so target propagation and participant proof remain gaps linked to [ADR 0059](../../architecture/decisions/adr-0059-causal-floor-cross-service-presentation-reads.md). `LOOK`, `QUICKLOOK`, movement refresh, localization, brief/color handling, and bounded error mapping are covered. Combat-sensitive brief-on-move and broader world-content localization remain incomplete.

### Communication, Social, and Presence

- Current behavior/proof: `SAY`, same-room `WHISPER`, online `TELL`, Social chat persistence, mail APIs, friends, guild APIs, presence reads, privacy settings, recipient delivery, and speech normalization are live at bounded service/API seams; focused communication, social, presence, privacy, moderation, and cross-service tests cover those seams.
- Local gaps linked to [ADR 0147](../../architecture/decisions/adr-0147-explicit-communication-classes-and-owner-delivery.md), [ADR 0148](../../architecture/decisions/adr-0148-social-relationship-authority-and-entity-owned-value.md), [ADR 0149](../../architecture/decisions/adr-0149-communication-type-specific-history-and-retention.md), and [ADR 0150](../../architecture/decisions/adr-0150-closed-observer-views-and-profile-scoped-shout.md) include offline `TELL`, profile-scoped `SHOUT`, richer topology/interception, type-specific history/acknowledgement, entity-owned social value/attachments, closed observer views, cross-pod delivery, first-party recipient presentation, and the canonical gameplay `WHISPER` recipient-scope migration. These ADR links identify gaps; they do not restate target policy.
- Presence/privacy drift remains tracked against [ADR 0026](../../architecture/decisions/adr-0026-global-roles-do-not-grant-gameplay-authority.md) and [ADR 0046](../../architecture/decisions/adr-0046-bounded-friend-presence-with-private-by-failure-redaction.md); global-role inputs, `HIDDEN_STAFF`, and disconnect disposition remain local fixes rather than new design.

### First-Party Frontend

- Current implementation: `web-client` is a React/Vite/MUI/TanStack Query baseline with a generic WebSocket envelope/JSON consumer that parses payloads as `unknown`, plus local feature/form state. Its Vite production build now emits compiled assets under `dist/frontend-assets/`; semantic structured `PlayerOutput` consumption, the complete admitted runtime-bundle asset bootstrap, independent immutable frontend artifact/release metadata, unprivileged static host, richer player UX, admin/design-tool integration, and end-to-end browser proof are not implemented. The target boundary and independent-release proof requirements remain in [FRONT-01](../../architecture/decisions/adr-0144-stateless-first-party-frontend-application-boundary.md).

## Active Gaps

- The normalized command envelope is still text-command-first: stage and client metadata are outside the richer envelope. NPC targeting, explicit ambiguity outcomes, localized aliases, active-registry discovery, richer schema-driven definitions, and broader action-metadata policy consumers remain incomplete. Stable item references are live, but the broader duplicate-NPC and action-family resolution model is not.
- The bounded stored game-authored HELP path is live, but rich authoring UI, localization-aware content, fuzzy or semantic search, related-topic behavior, stage-aware indexes, moderation/versioning, and broader dynamic command-discovery integration are not implemented.
- Structured recent transcript retention is bounded and is not a complete player archive/export facility. Player-controlled export, long-term history/search, and final raw-versus-normalized speech storage policy remain separate work.
- Communication has no offline `TELL`, `SHOUT`, configurable topology propagation, richer partial/full interception, game-configurable observer policy, distinct observer moderation ledger, or first-party optional-semantic recipient presentation. Classic-client semantic negotiation remains deferred and unadvertised under MCP-01.
- Localization is live for active built-in renderer outputs and room/exit prose; see the canonical [Input, output, and presentation](../../architecture/system-architecture-input-output-and-presentation.md#localization-and-translation) owner. Item, lore, and broader world-content adoption and locale-specific speech policy remain incomplete. Stored authored variants follow exact locale -> explicitly stored base language -> source locale; arbitrary regional sibling fallback and live provider translation remain out of scope, and no broader creator workflow/provider has been selected.
- Presentation still lacks combat-state-driven brief-on-move behavior, richer configurable prompt composition, broader prompt scheduling, and broader smart-client presentation policy.
- Presence and social surfaces have a bounded canonical runtime/read model, but broader activity-engine consumers, richer recent-presence policy, broader social consumers, and operator visibility and staff-capability enforcement remain incomplete.
- The independently released first-party static artifact, unprivileged static asset-hosting boundary, independent rollback, and richer browser product surface remain incomplete under [FRONT-01](../../architecture/decisions/adr-0144-stateless-first-party-frontend-application-boundary.md).
- Manual QA still needs to confirm that normal Telnet and generic WebSocket clients follow the same optional-browse, `LOGIN`, `PLAY`, in-game progression and that the first-party browser reaches the same gameplay binding semantics.
