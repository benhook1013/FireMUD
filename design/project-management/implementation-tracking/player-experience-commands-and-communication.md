# Player Experience, Commands, and Communication

## Target-State Authority

This is a non-normative implementation tracker for player-facing commands, communication, presence, and client behavior. Canonical target-state player-experience and cross-service contracts remain authoritative in [design/architecture](../../architecture/README.md) and the linked design sources below; this tracker owns current capability status, proof evidence, gaps, and handoffs, not normative design.

## Current Status

This tracker is the permanent reader-facing implementation record for player-facing commands, admission, presentation, communication, presence, and client behavior. Most bounded capabilities are live, including the stored game-authored HELP path; broader command interpretation, rich help authoring/discovery, elevated staff behavior, richer communication, and the independently released static frontend artifact/host boundary remain explicitly incomplete. Game Session currently has no independently verified gameplay-grant carrier, so newly written and returned presence uses the ordinary `PLAYER` projection; retained elevated cache values are presented as `PLAYER` until an ordinary presence update replaces them. Read-side demotion does not persist a change or extend TTL. R1423 qualifies this bounded receiving projection, with the source and recovery limits recorded below. The Vite frontend build now emits compiled assets under the reserved `frontend-assets` directory, but independently released hosting and browser proof remain absent. The output/reconnect lane remains partial where explicit structured schema versioning, strict complete-byte context bounds, durable logout invalidation, and broader client consumption are not yet proven. The earlier first-party post-`LOGOUT` replay defect is historical: current first-party `LOGIN`/`PLAY` deny and WebSocket reconnect suppresses retained private-context presentation. Durable logout invalidation and episode/generation-qualified replay remain gaps; stored rows are preserved.

Packet 5 moderation/communication/social provenance is represented by [ADR 0146](../../architecture/decisions/adr-0146-owner-local-moderation-enforcement.md), [ADR 0147](../../architecture/decisions/adr-0147-explicit-communication-classes-and-owner-delivery.md), [ADR 0148](../../architecture/decisions/adr-0148-social-relationship-authority-and-entity-owned-value.md), [ADR 0149](../../architecture/decisions/adr-0149-communication-type-specific-history-and-retention.md), and [ADR 0150](../../architecture/decisions/adr-0150-closed-observer-views-and-profile-scoped-shout.md); Packet 6 P0 shared consequences are represented by [ADR 0151](../../architecture/decisions/adr-0151-event-scoped-automated-tier-a-credential-compliance.md), [ADR 0152](../../architecture/decisions/adr-0152-phased-environment-bound-deployment-preflight-and-expected-bindings.md), [ADR 0153](../../architecture/decisions/adr-0153-measured-online-backup-rpo-and-future-pitr-trigger.md), [ADR 0154](../../architecture/decisions/adr-0154-automated-recovery-proof-and-differentiated-traffic-open-gates.md), [ADR 0155](../../architecture/decisions/adr-0155-automated-event-classified-post-restore-trust-reset.md), [ADR 0156](../../architecture/decisions/adr-0156-risk-tiered-progressive-rollout-with-compatibility-bounded-rollback.md), [ADR 0157](../../architecture/decisions/adr-0157-dependency-classified-liveness-readiness-and-route-admission.md), [ADR 0158](../../architecture/decisions/adr-0158-simplified-observability-degradation-without-fallback-alert-authority.md), and [ADR 0159](../../architecture/decisions/adr-0159-profile-dependent-independent-deadman-and-public-path-monitoring.md) where player-facing delivery, history, or privacy boundaries are affected. ## Current Gaps

- The [Social UUID preparation boundary](#communication-social-and-presence) temporarily rejects parent-issued numeric callers and has incompatible outbound peer readers; final supported UUID behavior is restored through #3360 and #2972, with service-local safety gaps still explicit.
- Friend-presence reads still lack snapshot-bound pagination and bounded-page proof; complete these against the [Friend Presence Privacy Contract](../../architecture/microservices/social-groups-service/api-contracts.md#friend-presence-privacy-contract).
- Friend-presence continuation still needs current friendship and block-state revalidation; complete this against the [Friend Presence Privacy Contract](../../architecture/microservices/social-groups-service/api-contracts.md#target-state-snapshot-chunking-pagination-and-failure-precedence).
- Game Session has no independently verified gameplay-grant carrier today, so presence currently uses `PLAYER`; R1423 executed bounded receiving proof during the preparation committed as `d12c0ab2e7a7d1d40f62991e3d097bd9090cc2ef` (137 selected units plus six real-Redis cases; original aggregate and fixture recovery are distinguished below). That proof was not rerun on the current review head. Production tenant-gameplay-grant qualification, admission, and broader runtime authorization/disclosure proof remain incomplete under [ADR 0026](../../architecture/decisions/adr-0026-global-roles-do-not-grant-gameplay-authority.md) and the canonical [authentication owner](../../architecture/system-architecture-authentication.md).

### Admission, Commands, and Capabilities

Current text `WORLDS` remains an optional pre-login public browse. Caller-free `REALMS` exposes public-production realms; authenticated private-realm discovery remains incomplete. Direct-text `CHARS` returns unavailable without calling Entity’s legacy roster adapter; the supported Account bootstrap/HTTP roster is separate. `HELP`/`PLAY` guidance uses known character names rather than numbered roster browsing. Current text `PLAY` evaluates fresh entitlement before membership/grant and later actor/binding checks, validates Account-emitted lifecycle and independent authority generation, and requires coherent `ACTIVE` admitting membership. Eligible missing or `INACTIVE` public membership returns non-actionable `JOIN_REQUIRED` only when joining policy permits repair; closed enrollment blocks repair, not an existing `ACTIVE` member by itself. Private membership and grant denials use `NON_PUBLIC_ENROLLMENT_REQUIRED` and `REALM_ACCESS_DENIED`; unsafe or unavailable evidence uses `AUTH_UNAVAILABLE`. Account connect-token issuance separately validates bootstrap identity and retained scope, then returns `AUTH_UNAVAILABLE` before admission-authority reads, cached replay, or token work; [Account runtime status](../../architecture/microservices/account-service/runtime-and-data.md) owns that boundary.
