## 2026-11-01 — Filesystem read-only checks can miss bind mounts

During protected projection compatibility work, a proposed Java `Files.getFileStore(path).isReadOnly()` guard was rejected before implementation. OpenJDK 21 discovers Linux filesystem boundaries using device changes and reads the selected mount entry’s flag; a same-device bind mount can therefore be attributed to an ancestor with different read-only state. File modes and sticky bits are also insufficient. The bounded repair uses exact current-process mountinfo evidence, visible ancestry and pre/post comparison while preserving owner and AtomicWriter child checks. Twelve physical mount cases now pass through both actual packaged readers, including same-device writable binds and strict child/owner/digest denial. This establishes neither a deployed outage nor platform provenance. See [Game Session projection compatibility](../architecture/microservices/game-session-service/operations.md#protected-readiness-projection-compatibility).
