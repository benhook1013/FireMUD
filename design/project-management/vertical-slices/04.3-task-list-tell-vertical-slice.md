# Tell Communication Vertical Slice Task List

## Goal and Status

Goal: implement the first direct non-room-scoped communication mode, `tell`, on top of the shared communication infrastructure. Status: planned; defaults are agreed, but implementation has not started.

Default `tell` semantics agreed so far:

- `tell` is a direct character-to-character communication action;
- it is not room-scoped by default;
- sender and target receive full content;
- no observer path exists by default unless a game rule/capability explicitly enables one;
- this built-in gameplay `tell` is live/online only and does not collapse into mail.

## 1. Protocol and UX

- [ ] Add `TELL <character> <text>` to the Minimal Text Command Protocol as a standard built-in communication action.
- [ ] Define the canonical prose/transcript for:
  - sender,
  - target,
  - and failure outcomes such as target offline or unreachable.
- [ ] Document explicitly that `tell` is not mail and does not imply asynchronous delivery.

## 2. Game Logic Behaviour

- [ ] Implement `tell` as a communication type using the shared communication infrastructure from `04.1`.
- [ ] Resolve the direct target through authoritative gameplay/account/character identity rules rather than through ad hoc parser shortcuts.
- [ ] Keep `tell` outside room scope by default while still flowing through Game Logic so gameplay interception/perception rules can later participate if a game adds that capability.
- [ ] Add unit tests covering:
  - successful live tell,
  - target offline,
  - invalid target,
  - muted/silenced sender,
  - and backend failure propagation.

## 3. Social & Groups Participation

- [ ] Use Social & Groups for the parts it owns:
  - direct-message delivery fanout,
  - moderation,
  - durable history if configured,
  - and presence or membership checks where applicable.
- [ ] Document the contract so Social & Groups receives explicit communication metadata and does not become an alternative top-level execution path.
- [ ] Keep the design open for future gameplay interception or surveillance mechanics on direct tells without requiring a path rewrite.

## 4. Game Session and Rendering

- [ ] Add or refine a `TellCommandHandler` (or equivalent adapter) in Game Session that packages the communication action and delegates all domain behaviour to Game Logic.
- [ ] Define canonical protocol-level success and failure shapes for `tell`.
- [ ] Add WebSocket and Telnet rendering tests that prove the same semantics over both transports.

## 5. Cross-Service Regressions

- [ ] Add cross-service coverage for:
  - successful live tell,
  - target offline,
  - target invalid,
  - and backend failure.
- [ ] Capture canonical transcript fixtures for sender and target.
- [ ] Confirm the regression flow still demonstrates:
  - Game Session -> Game Logic -> Social & Groups.
