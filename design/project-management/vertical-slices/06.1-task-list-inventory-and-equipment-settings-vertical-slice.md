# Inventory and Equipment Settings Vertical Slice Task List

## Goal and Status

Goal: fold the new inventory, room-ground container, and equipment behavior into the platform settings model once `06` starts landing, so slot/body-layout rules, inventory presentation, and equipment compatibility do not calcify as code-only policy. Status: planned.

This slice intentionally follows `06`. The underlying inventory/equipment model should land first; this follow-up then surfaces the meaningful tenant/game behavior settings into the canonical platform settings framework introduced by `02.9`.

## 1. Domain Inventory

- [ ] Audit the inventory/equipment behavior introduced by `06` and classify each setting candidate as:
  - operator/runtime tuning;
  - tenant/game behavior policy;
  - or internal-only implementation detail.

## 2. Inventory Settings Surface

- [ ] Define the first canonical `inventory` settings groups, such as:
  - `inventory.presentation`
  - `inventory.selection`
  - `inventory.validation`
- [ ] Surface baseline behavior for:
  - `INVENTORY`
  - `GET`
  - `DROP`
  - item selector rules
  - room-ground item visibility in player-facing transcripts.

## 3. Equipment Settings Surface

- [ ] Define the first canonical `equipment` settings groups, such as:
  - `equipment.bodyLayouts`
  - `equipment.slotCompatibility`
  - `equipment.presentation`
- [ ] Surface configurable body-layout and slot semantics as game-defined data rather than platform-hardcoded truth.
- [ ] Document how equipment compatibility metadata is surfaced through the settings/design model without breaking the authoritative persistence model in Entity Management.

## 4. Persistence and Effective Config

- [ ] Decide which inventory/equipment settings are tenant/game-configurable versus operator-capped.
- [ ] Document how effective inventory/equipment config is resolved for gameplay validation and rendering.

## 5. Docs and Generated Reference

- [ ] Add a generated or generation-ready settings reference for inventory and equipment domains.
- [ ] Update the `06` docs to reference surfaced settings rather than leaving all policy implicit in implementation notes.

## 6. Final QA Checklist

- [ ] Confirm the resulting settings model lets later games override slot/body-layout and presentation policy without rewriting the inventory architecture.
- [ ] Confirm inventory/equipment behavior now fits the same repeatable settings pattern as reconnect, communication, and room-view domains.
