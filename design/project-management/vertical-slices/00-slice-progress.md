4. [07.4 Unified Actor Model](./07.4-task-list-unified-actor-model-vertical-slice.md)
   Decision locked: every active gameplay being has a persisted opaque runtime actor. Player actors are scoped by `{tenantId, gameInstanceId, characterId}`; NPC actors are scoped by runtime NPC instance; reconnect changes presence rather than identity. Each actor has one DML-authored main disposition. Commands/actions carry separate ordered `admissionTags`; continuous conditions/equipment only add denials to that base policy, while feature availability and session-stage gates remain separate. Explicit instant condition removal/prevention or disposition transitions own recovery and lifecycle exceptions. Transport presence remains separate.
5. [07 Entity Stats and Conditions](./07-task-list-entity-stats-and-conditions-vertical-slice.md)
   Decision locked: game-specific stats, resources, conditions, tags, effect values, floor transitions, actor dispositions, and targeting policies/default-path bindings are versioned DML in a typed release bundle. Condition definitions own deterministic replace/refresh/stack/parallel and cure behavior. Bounded-resource capacity normalization is an effective tenant/game policy, with optional declaration-specific overrides for continuous source transitions and no read-time current-state mutation. Curated base experience profiles and optional packs materialize ordinary editable DML into Draft versions without live fallback inheritance and may seed editable ordinary game settings. Remaining: Entity Management now has evaluated actor state, persisted resource/condition rows, shared effect evaluation, equipped-item contributions, replay-guarded action-state mutation/expiry, and the first release-admitted authored action-effect execution; generic catalog implementation, resource-cost mutation, multi-effect actions, and damage/mitigation remain future work.
6. [07.1 Shared Effect Engine](./07.1-task-list-shared-effect-engine-vertical-slice.md)
   Decision locked: Game Logic resolves cross-actor effects into an idempotent `ResolvedEffectPlan`; same-region required targets apply atomically and cross-region legs report durable individual outcomes. Platform target selectors only form safe candidate sets; release-pinned DML targeting policies decide game-specific eligibility from optional authored facts, so visibility/targetability are not universal actor fields. Policies separate non-disclosing discovery from eligibility with policy-approved feedback. Costs and cooldowns are durable actor timed state committed only at action execution, with Redis timers as reconstructible scheduling projections. Durable action outcomes carry separate commit/completion state and emit semantic presentation events that Game Session renders without inferring gameplay semantics. One lifecycle-aware effect grammar serves equipment, conditions, actions, and later auras: continuous sources contribute while attached and instant effects mutate once. Remaining: the typed evaluation seam now consumes active conditions, equipment payloads, replay-guarded action states, and the first admitted authored `APPLY_ACTION_STATE` declaration. The honest tail is generic authored stat/condition definitions, additional effect kinds, resource-cost/cooldown implementation, and combat consumers.
