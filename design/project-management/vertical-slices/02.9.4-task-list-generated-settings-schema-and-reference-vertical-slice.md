# Generated Settings Schema and Reference Vertical Slice Task List

## Goal and Status

Goal: complete the first real generated settings reference flow so the platform settings schema can produce operator/admin-facing documentation and machine-readable metadata from one source of truth. Status: planned.

This slice follows `02.9` and should build on the typed metadata already surfaced in the pre-`06` domains.

## Scope

- Generated machine-readable settings schema
- Generated operator/admin-facing reference output
- Canonical metadata coverage for surfaced settings
- Alignment between schema, docs, and runtime ownership model

## Key Tasks

- [ ] Define the first generated schema output format for surfaced settings domains.
- [ ] Generate one consolidated settings reference from the typed settings metadata/source of truth.
- [ ] Ensure generated output carries:
  - key/path
  - description
  - default
  - valid range or enum
  - scope/owner
  - hot-reloadability
  - advanced flag
  - example value
- [ ] Keep generated output aligned with the canonical ownership and precedence model rather than becoming a second hand-maintained reference.
- [ ] Document how later admin/creator tooling should consume the same schema output.

## Tests

- [ ] Add generation tests or validation checks proving surfaced domains appear in the generated outputs.
- [ ] Add doc/schema validation so generated reference drift is caught automatically.

## Notes

- This slice is about making the settings model publishable and inspectable, not about building the full UI on top of it.
