# LOOK and Transcript Settings Vertical Slice Task List

## Goal and Status

Goal: fold `LOOK`, `QUICKLOOK`, reconnect screen-buffer policy, and transcript rendering defaults into the platform settings model so room-view behavior evolves through explicit settings rather than fixed renderer assumptions. Status: partially implemented.

## Implementation Notes

- Reconnect and transcript policy now have a real typed settings seam in `FiremudReconnectionProperties`:
  - resume window;
  - stale-resume fallback;
  - screen-buffer TTL and bounds;
  - look-cache TTL;
  - reconnect prompt flags.
- Those settings are now consumed by the shared Redis-backed look cache and screen-buffer services in `common-data-runtime`.
- `LOOK` has also started moving toward a structured view model through `LookViewOutput` and `TextPlayerOutputRenderer`.
- The slice is still incomplete:
  - runtime rendering still produces one fixed classic text shape;
  - `QUICKLOOK` is not implemented;
  - look/transcript behavior is not yet tenant-configurable;
  - there is no generated reference for the surfaced settings yet.

This slice follows `02.9`. It should not redesign the `LOOK` ownership split. It should surface the already-agreed room-view and transcript rules into the canonical settings model and generated docs.

## 1. Domain Inventory

- [ ] Audit the existing `LOOK`, reconnect screen-buffer, and transcript-shape rules currently expressed in docs, tests, and rendering code.
- [ ] Classify each behavior as:
  - operator/runtime tuning;
  - tenant/game behavior policy;
  - or internal-only implementation detail for now.

## 2. Room-View Settings Surface

- [ ] Define the first canonical `look` settings groups, such as:
  - `look.rendering`
  - `look.visibility`
  - `look.variants`
- [ ] Surface the agreed classic default transcript shape:
  - room title;
  - one composed descriptive block;
  - exits;
  - prompt outside the body.
- [ ] Capture `QUICKLOOK` as a standard built-in variant that omits room-description prose while reusing the same underlying structured room-view model.

## 3. Transcript and Screen-Buffer Settings Surface

- [ ] Define the first canonical transcript/screen-buffer settings groups, such as:
  - `transcript.reconnectBuffer`
  - `transcript.rendering`
  - `transcript.overlayPolicy`
- [ ] Surface the agreed reconnect screen-buffer rules:
  - minimum message floor;
  - minimum line floor;
  - byte ceiling;
  - short TTL;
  - fresh `LOOK` after replay.
- [ ] Document how overlays like combat/hazards/ambient effects should later fit into configurable transcript rendering without reopening the base `LOOK` contract.

## 4. Persistence and Effective Config

- [ ] Decide which room-view and transcript settings are tenant/game-configurable versus operator-capped.
- [ ] Document how effective config is resolved for room-view rendering and reconnect redraw behavior.

## 5. Docs and Generated Reference

- [ ] Add a generated or generation-ready settings reference for `look` and transcript domains.
- [ ] Update the `03` design docs to reference surfaced settings where appropriate rather than only prose contracts.

## 6. Final QA Checklist
