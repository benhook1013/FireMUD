# Durable Reconnect Transcript Canonical Bounds Vertical Slice

## Goal and Status

Goal: converge durable reconnect transcript ordering and retention onto the canonical structured-entry contract so a cache or timestamp tie cannot change the replay window. Status: complete at the current bounded boundary.

## Boundary

- Use the existing sequence-backed `resume_transcript_entry.id` as the durable replay ordering token.
- Count the canonical structured-entry envelope, including identity, ordering token, structured payload, and rendered compatibility text, for every byte-bound decision.
- Reject one complete entry that exceeds the hard byte bound; do not retain a partial or truncated record.
- Enforce an explicit maximum retained-entry count before soft/hard byte eviction.
- Reaccount previously written durable rows before applying current bounds, then make Redis mirror the resulting durable window.
- Validate persisted reconnect settings before they can silently normalize into a different effective policy.

## Out of Scope

- Long-lived Player Transcript Archive and Export.
- Changing which output classes are replay eligible.
- Altering the normal `LOGIN` / `PLAY` reconstruction sequence after replay.

## Proof

- Unit proof covers canonical structured-envelope byte sizing, oversized-entry rejection, entry-count trimming, legacy-row reaccounting, and Redis mirror trimming.
- Repository integration proof covers sequence-token ordering for entries with equal timestamps.
- Effective-settings and settings-authority proof covers the new maximum-entry override and invalid persisted values.
