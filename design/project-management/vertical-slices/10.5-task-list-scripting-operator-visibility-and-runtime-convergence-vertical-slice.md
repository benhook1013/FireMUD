# Scripting Operator Visibility and Runtime Convergence Vertical Slice

## Goal and Status

Goal: give operators one coherent convergence and visibility model across script-patch readiness, plugin publication versus activation, rollout state, drain status, and scripting runtime failures so tooling stops inferring truth from partial read models. Status: in progress.

## Why This Slice Exists

The repo already has substantial control-plane and observability design for scripting, but the operator-facing picture is still spread across multiple docs and event families. This slice gives that visibility work a bounded home.

## Implementation Notes

Implementation is underway through the runtime convergence substrate already landed in `10.1`, `10.3`, and `10.4`: durable work items, handler-scoped audit rows, real pending-work cancellation, status-safe claim transitions, current script-patch status reads derived from durable work, the first `GetAutomationDrainStatus` read over durable work-item scopes, the first `GetAutomationPinConvergence` read over the shared runtime-state observation already used by Automation-side checks, dead-letter listing plus controlled replay, a durable plugin runtime registry with activation/disable/drain state transitions plus last-request/actor visibility, Game Design-backed plugin publication reads plus immutable published release-bundle `abilitySchemaDigest` and `baseVersionId` activation checks, a stronger shared Game Session runtime-state read for instance metadata and pin provenance, scheduled terminal outbox cleanup, and the first per-instance script-patch rollout read APIs with explicit freshness flags now exist. Richer event-projected rollout history, real admission-epoch-aware drain/convergence reads, and the remaining signer/component-policy gates still remain.

## Scope

- operator-facing read models and freshness expectations
- script-patch readiness versus instance rollout visibility
- plugin publication versus runtime activation visibility
- drain/convergence/rollback status surfaces for scripting operations

## Out of Scope

- raw sandbox/runtime implementation details except where they surface in operator truth
- creator-facing editor UX
- broader security/compliance/operator-control-plane domains outside scripting

## Locked Direction

- design-time publication, tenant readiness, and instance activation are distinct truths and must remain so in operator tooling.
- read-model freshness and projection lag are explicit contracts, not incidental details.
- operator workflows consume canonical reads/events rather than reconstructing state from raw tables or logs.
- scripting convergence must remain scoped enough that operators can distinguish stale projections from failed operations.

## Current Remaining Work

- extend the first live per-instance rollout reads into fuller event-projected convergence history instead of today’s direct-runtime-plus-local-work summary.
- upgrade `GetAutomationDrainStatus` from its current durable-work summary (`admissionEpoch=0`) to a real pause/admission-epoch-aware drain model once rollback admission controls exist.
- upgrade `GetAutomationPinConvergence` from its current shared-runtime observation to a replayable Automation-owned pin projection that can surface non-empty `lastObservedControlPlaneRequestId`.
- prove freshness/staleness signaling across later drain/convergence read models, not only the current script-patch rollout surface.
- keep plugin publication events and runtime activation events separate in tooling and storage.
- implement the remaining readiness/cancellation taxonomy and operator read-model separation so the live surfaces match the canonical design; current script-patch status summaries, dead-letter listing plus replay, plugin runtime state transitions, Game Design publication plus immutable runtime compatibility checks (`baseVersionId` and `abilitySchemaDigest`), and outbox-retention cleanup are now live.
