# Scripting Operator Visibility and Runtime Convergence Vertical Slice

## Goal and Status

Goal: give operators one coherent convergence and visibility model across script-patch readiness, plugin publication versus activation, rollout state, drain status, and scripting runtime failures so tooling stops inferring truth from partial read models. Status: in progress.

## Why This Slice Exists

The repo already has substantial control-plane and observability design for scripting, but the operator-facing picture is still spread across multiple docs and event families. This slice gives that visibility work a bounded home.

## Implementation Notes

Implementation is underway through the runtime convergence substrate already landed in `10.1` and `10.3`: durable work items, handler-scoped audit rows, real pending-work cancellation, status-safe claim transitions, and scheduled terminal outbox cleanup now exist. Operator-facing read APIs for patch readiness, rollout/drain convergence, dead-letter replay, and plugin activation visibility still remain.

## Scope

- operator-facing read models and freshness expectations
- script-patch readiness versus instance rollout visibility
- plugin publication versus runtime activation visibility
- drain/convergence/rollback status surfaces for scripting operations

## Out of Scope

- raw sandbox/runtime implementation details except where they surface in operator truth
- creator-facing editor UX
- broader security/compliance/operator-control-plane domains outside scripting

## Locked Direction

- design-time publication, tenant readiness, and instance activation are distinct truths and must remain so in operator tooling.
- read-model freshness and projection lag are explicit contracts, not incidental details.
- operator workflows consume canonical reads/events rather than reconstructing state from raw tables or logs.
- scripting convergence must remain scoped enough that operators can distinguish stale projections from failed operations.

## Current Remaining Work

- land the first operator-visible convergence/read-model surfaces on top of the documented control-plane APIs and events.
- prove freshness/staleness signaling in read models that project scripting runtime state.
- keep plugin publication events and runtime activation events separate in tooling and storage.
- implement the remaining readiness/cancellation taxonomy and operator read-model separation so the live surfaces match the canonical design; outbox-retention cleanup is now live.
