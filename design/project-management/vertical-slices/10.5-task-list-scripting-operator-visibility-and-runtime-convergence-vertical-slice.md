# Scripting Operator Visibility and Runtime Convergence Vertical Slice

## Goal and Status

Goal: give operators one coherent convergence and visibility model across script-patch readiness, plugin publication versus activation, rollout state, drain status, and scripting runtime failures so tooling stops inferring truth from partial read models. Status: in progress.

## Why This Slice Exists

The repo already has substantial control-plane and observability design for scripting, but the operator-facing picture is still spread across multiple docs and event families. This slice gives that visibility work a bounded home.

## Scope

- operator-facing read models and freshness expectations
- script-patch readiness versus instance rollout visibility
- plugin publication versus runtime activation visibility
- drain/convergence/rollback status surfaces for scripting operations

## Out of Scope

- raw sandbox/runtime implementation details except where they surface in operator truth
- creator-facing editor UX
- broader security/compliance/operator-control-plane domains outside scripting

## Locked Direction

- design-time publication, tenant readiness, and instance activation are distinct truths and must remain so in operator tooling.
- Game Design publication state, Automation runtime activation state, and per-instance convergence/drain state remain separate canonical reads even when operator tooling presents them side by side.
- operator-facing APIs may cross-link those truths by stable identifiers, but they do not collapse them into one synthetic status row or one shared lifecycle.
- read-model freshness and projection lag are explicit contracts, not incidental details.
- operator workflows consume canonical reads/events rather than reconstructing state from raw tables or logs.
- scripting convergence must remain scoped enough that operators can distinguish stale projections from failed operations.

## Current Remaining Work

- the broad freshness/staleness contract is now live across the current drain/convergence family; remaining work in this slice is no longer about whether reads should expose freshness, but about carrying that explicit contract into any later operator-facing convergence surfaces that are added.
- keep implementing publication-versus-activation separation under the locked model now that append-only runtime plugin events exist alongside the current-row registry, `GetPluginStatus` cross-links active/pending publication truth from Game Design, and Game Design publication reads now include a tenant-scoped listing surface; remaining work is later operator presentation and event handling, not re-deciding whether those truths collapse together.
- implement the remaining readiness/cancellation taxonomy and operator read-model separation so the live surfaces match the canonical design; current script-patch status summaries plus publication metadata, durable readiness projection and supersession semantics, dead-letter listing plus replay, plugin runtime state transitions, Game Design upload/publication reads plus durable design-time status reasons, publication-time base-version/signer/policy validation, immutable runtime compatibility checks (`baseVersionId` and `abilitySchemaDigest`), signer/component activation gates, and outbox-retention cleanup are now live.
