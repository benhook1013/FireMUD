# Automation Handoff and Tick Integration Vertical Slice

## Goal and Status

Goal: keep the Automation & Scripting to Game Session handoff on one canonical outbox/queue/tick seam so scripting-generated commands enter gameplay execution through the same tick safety model as player commands. Status: in progress.

## Why This Slice Exists

This seam is already central to the runtime, but it is not yet represented as a dedicated slice. Without one, future scripting work can drift into direct tick writes, partial queue shortcuts, or unclear ownership between Automation and Game Session.

## Implementation Notes

Implementation is underway. Automation-owned Redis queue and quota helpers now use the canonical instance-aware `automation:queue:{tenantInstanceTag}:*` and `automation:quota:<tenantId>:<scriptId>` key families, while the older `automation:tick:*` staging path has been retired from the live/runtime design because durable outbox execution already owns the real handoff seam. `automation:queue:*` entries are now the documented durable outbox-pointer envelope (`schemaVersion`, `outboxWorkItemId`, and bounded identity metadata) rather than raw event payloads. Game Session also now exposes the idempotent `EnqueueAutomationCommandIfAbsent` handoff surface and persists the automation dispatch/work-item correlation on the gameplay command ledger before staging the command into the tick queue. Automation now has the matching handoff service boundary: given an emitted command from a durable work item, it derives the per-command `automationDispatchId`, calls Game Session, and maps `ENQUEUED`, duplicate/no-op, and rejection outcomes back to work-item/audit state. The handoff seam now also persists durable per-command `script_handoff_events` and exposes them through `ListScriptHandoffEvents` so richer multi-command output remains operator-visible instead of collapsing into one work-item terminal row. The queue/index side is also now explicitly reset-tolerant instead of being ingress-only projection state: Redis drains dedupe by `outboxWorkItemId`, a bounded scheduled rebuild republishes missing queue pointers from durable `PENDING_EVALUATION` / `EVALUATING` work items, a bounded inspector loop now publishes orphan/oldest-age queue health metrics from the queue projection plus durable outbox state, and a first production executor claims durable work items, evaluates the current command-emission format, and hands those commands to Game Session without bypassing the dispatch identity contract. That evaluator now supports command-specific `targetEntityId` templates, a first structured emitted-command shape (`commandAlias` + templated `arguments`), and first multi-target fan-out from one emitted command node via templated `targetEntityIds[]`, while `ListScriptHandoffEvents` preserves the rendered command text beside dispatch identity.

## Scope

- durable scripting work-item persistence and derived coordination indexes
- `automation:queue:*` / `automation:tick:*` staging semantics
- Game Session handoff APIs and tick-fence expectations
- canonical ownership split between Automation runtime and Game Session tick execution

## Out of Scope

- broader non-scripting command durability hardening
- sandbox execution semantics before work items are produced
- frontend/operator UX beyond the observability needed to prove handoff

## Locked Direction

- Automation & Scripting never writes Game Session tick keys directly.
- durable work truth and derived coordination indexes remain separate concerns.
- scripting-generated commands must enter the same tick safety/fairness path as gameplay commands.
- queue/index loss may be tolerable only when the documented rebuild and observability contracts hold.

## Current Remaining Work

- tighten ownership tests so Automation cannot bypass Game Session tick invariants.
- keep observability and recovery docs plus control-plane reads on the same handoff identities now that durable per-command handoff events exist.
- extend the first production executor beyond the current targeted command-template format toward richer graph/runtime output without changing the handoff identity seam.
- decide whether the next consumer evolution should drain queue-pointer envelopes directly or keep the queue as rebuildable projection while the durable claim/evaluate loop remains DB-driven.
- keep hardening queue lifecycle and rebuild proof so `automation:queue:*` remains a reset-tolerant derived index rather than an unbounded alternate source of work truth as more statuses and consumer paths land.
