# Non-Edge Failover Invisibility Vertical Slice Task List

## Goal and Status

Goal: make Game Session, Game Logic, and other non-edge gameplay service restarts operationally invisible to connected clients in the common case so edge reconnect remains the true visible failure boundary. Status: planned.

This follow-up is intentionally separate from `02.3`. The current reconnect slice already documents that visible reconnect after non-edge restart is implementation debt; this slice is the work to remove that debt.

## 1. Service-State Audit

- [ ] Re-read the Game Session, Game Logic, Redis, and protocol-bridging docs and verify that meaningful live gameplay state is externalized rather than hidden in process-local memory.
- [ ] Identify any remaining process-local state that prevents same-type instances from taking over safely after restart.
- [ ] Document one canonical takeover-ready ownership model for:
  - gameplay session context,
  - command/tick coordination,
  - in-flight response reconstruction,
  - and reconnect hints or screen-buffer access.

## 2. Backend Rebind Behaviour

- [ ] Ensure an existing edge connection can survive Game Session restart by rebinding backend handling from shared state rather than forcing visible `LOGIN` / `PLAY`.
- [ ] Ensure the same principle holds for Game Logic restart where spatial/gameplay state is already externalized.
- [ ] Define the bounded behavior for in-flight commands during backend failover:
  - what may be lost,
  - what must complete,
  - and what current-state reconstruction the client sees afterward.

## 3. Edge and Retry Semantics

- [ ] Keep the client-visible retry taxonomy honest:
  - edge process loss may still drop sockets bound to that process;
  - non-edge restart should not masquerade as a clean logout.
- [ ] Ensure the edge rebind and retry behavior is documented separately from the client-visible reconnect contract so invisible failover does not get confused with explicit reconnect.

## 4. Regression Coverage

- [ ] Add focused tests proving that non-edge restart causes at most a bounded stall rather than a visible reconnect flow.
- [ ] Add at least one proof for Game Session restart and one for Game Logic restart.
- [ ] Keep the coverage bounded; do not turn this into a full cluster-chaos matrix.

## 5. Final QA Checklist

- [ ] Manually verify one Game Session restart and one Game Logic restart while a client remains connected at the edge.
- [ ] Confirm the client sees continued gameplay after a brief stall rather than a forced explicit reconnect flow.
