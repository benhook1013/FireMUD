# Preview Internal gRPC Transport Alignment Vertical Slice

## Goal

Make the hosted preview environment's internal gRPC transport stance explicit, operationally coherent, and temporary by documenting the current plaintext exception, preserving the canonical mTLS target state, and defining the conditions for removing the exception.

## Why This Slice Exists

Hosted preview needs to stay reviewer-usable, but preview debugging has already shown how easy it is for undocumented transport drift to waste time:

- preview appeared to be using mTLS because certs and `FIREMUD_GRPC_*` variables were present
- Spring gRPC `1.0.x` server TLS was not actually enabled by the old property shape
- clients and servers silently disagreed about TLS vs plaintext
- preview stalled in Helm wait with very little actionable signal

The design should not leave that as tribal knowledge. FireMUD needs one explicit statement of:

- what preview does today
- why that is temporary
- what the target state remains
- what concrete exit criteria remove the exception

## Scope

- Document that hosted preview currently allows plaintext internal gRPC as a preview-only implementation note.
- State that the canonical target state remains mTLS for internal gRPC in non-local environments.
- Define the explicit exit criteria for removing preview plaintext:
  - Spring gRPC server TLS migrated to SSL bundles
  - preview rollout proven with mTLS
  - old legacy server-TLS property patterns removed
  - CI/static guards added
- Ensure preview docs, deployment-environment docs, and gRPC/security docs all say the same thing.
- Update the design docs in the same change so the preview exception is not left implicit in comments or workflow lore.

## Out of Scope

- Implementing the SSL-bundle migration itself
- Designing a different preview topology
- Changing the long-term mTLS target state

## Architecture Notes

- Preview transport exceptions are allowed only when they are:
  - narrowly scoped,
  - documented in design,
  - paired with follow-up cleanup slices,
  - and clearly marked as non-canonical.
- Preview must not silently create a second long-term transport model.
- This slice exists to keep the real architecture legible while preview iteration continues.

## Acceptance Shape

- Design docs explicitly state the preview/plaintext exception and the mTLS target state.
- The preview README, security architecture doc, and gRPC architecture doc all describe the same temporary exception and removal criteria.
- The preview slice index points to the transport-alignment follow-up.
- Exit criteria for removing preview plaintext are written down in one place rather than left in chat or commit lore.
