# Communication and Prompt Settings Vertical Slice Task List

## Goal and Status

Goal: fold communication and prompt behavior into the new platform settings model so `say`, `whisper`, `tell`, reconnect prompt handling, and later first-party/MCP-aware presentation stop depending on hardcoded defaults scattered across services. Status: partially implemented.

## Implementation Notes

- Communication now has an explicit surfaced operator setting for maximum message length via `CommunicationProperties`, `firemud.communication.max-message-length`, and generated configuration metadata in `game-logic-service`.
- The first built-in communication mode defaults are now surfaced and enforced in Game Logic via:
  - `firemud.communication.defaults.say-enabled`
  - `firemud.communication.defaults.whisper-enabled`
  - `firemud.communication.defaults.tell-enabled`
  - `firemud.communication.defaults.whisper-observer-metadata-enabled`
- The first canonical settings groups for this area are now explicit:
  - `communication.defaults`
  - `prompts.coalescing`
  - `prompts.transportPresentation`
- Prompt-related knobs now exist in typed config objects:
  - reconnect-oriented transcript/buffer policy lives in `FiremudReconnectionProperties`
  - prompt enablement, reconnect re-emit behavior, and burst-window defaults live in `PresentationProperties`
- Current effective-config behavior is now explicit:
  - communication defaults resolve directly in Game Logic from `CommunicationProperties`, with a first operator/debug read surface now exposed at `/actuator/settings/effective/communication`;
  - prompt defaults resolve through Game Session's first effective-settings read surface from `PresentationProperties`;
  - both are still operator/file-env-backed today rather than tenant/game-overridable runtime settings.
- Built-in communication prose and prompt presentation still flow through the shared communication/output model:
  - operator defaults may enable, disable, or adjust built-in mode behavior;
  - later tenant/game override should still feed the same shared communication and prompt pipelines rather than bypassing them with ad hoc strings.
- Generation-ready settings references now exist in:
  - `design/architecture/microservices/game-logic-service/configuration.md`
  - `design/architecture/microservices/game-session-service/configuration.md`
- The canonical layered ownership and precedence model for these settings is now captured in `design/architecture/system-architecture-settings-model.md`.
- Prompt payloads now carry a first minimal structured status field list alongside classic prompt text, although first-party web still consumes the same text WebSocket surface today.
- The slice is still incomplete:
  - only a first bounded subset of communication defaults is actively enforced for communication;
  - communication settings still do not participate in the Game Session effective-settings read surface;
  - prompt handling still spans the canonical domains already agreed here rather than one dedicated prompt authority object;
  - tenant/game override resolution is still future even though the current operator-default layer is explicit;
  - there is still no first-party structured prompt consumption.

This slice follows `02.9`. It should not redesign the communication architecture itself. It should surface the already-agreed communication and prompt policy into the layered settings model with operator caps, tenant/game overrides, and generated reference docs.
