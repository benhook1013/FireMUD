# LOOK Instrumentation and Monitoring

This reference describes the metrics/logs generated by the data-driven `LOOK` pipeline so operators can trace a Telnet/WebSocket request end-to-end.

## Metrics

- `gamesession.command.look.invocations` — incremented every time Game Session receives an authenticated `LOOK`. Emitted in `LookCommandHandler`.
- `gamesession.command.look.failures{error="<CODE>"}` — incremented when Game Session translates a gRPC failure into an `ERROR CODE` response. Supported codes: `ROOM_NOT_FOUND`, `WORLD_UNAVAILABLE`, `ENTITY_UNAVAILABLE`, `LOOK_UNAVAILABLE`, `UNEXPECTED`.
- `game_logic.look.response_time` (histogram/gauge) — measured around `LookAggregationService` so downstream latency is visible.
- `gamesession.command.communication.invocations{type="<type>"}` — incremented when Game Session routes a communication command through `CommunicationCommandHandler`, with `type` drawn from bounded command types such as `say`, `whisper`, and `tell`.
- `gamesession.command.communication.failures{type="<type>",error="<CODE>"}` — incremented when Game Logic or Social/Groups reports a delivery failure (`PERMISSION_DENIED`, `UNAVAILABLE`, etc.) so telemetry can diagnose why clients see `ERROR COMMUNICATION_NOT_DELIVERED`.
- `gamesession.command.say.invocations`, `gamesession.command.whisper.invocations`, and `gamesession.command.tell.invocations` — bounded per-command compatibility counters for the current communication capability.

Define alerts for sustained drops in `gamesession.command.look.invocations` or spikes in failure counts.

## Logs and proof

- **Game Logic**: `LookAggregationService` is the structured-result boundary. Focused proof logs/asserts the composed `LookResult` and typed failure outcomes, while downstream gRPC failures retain `WorldManagement` or `EntityManagement` source labels. The current `LookResultRenderer` `Rendered LOOK text` DEBUG/fixture path remains local diagnostic evidence only; it does not transfer player-facing renderer ownership to Game Logic.
- **Game Session**: `LookCommandHandler` logs `redis.session.lookup` entries at DEBUG, maps accepted outcomes to compact versioned `PlayerOutput`, and emits warnings such as `LOG WARN LOOK failed for tenantId=<tenantId> error=<ERROR>` whenever it maps a gRPC error to a protocol response. Focused proof logs/asserts the `PlayerOutput` and its deterministic text projection before delivery.

## Correlation & Tracing

- Use the shared tracing context and structured log fields emitted by the request/gRPC interceptors to connect drops in `gamesession.command.look.*` with issues in Game Logic or World/Entity services.
- For Telnet smoke tests, capture Redis `SessionContext` identifiers and use them as log filters to group repeated `LOOK` invocations across replays.

## Operational Guidance

- When a `LOOK` request fails, consult `gamesession.command.look.failures` to determine the error code, then use structured logs with `tenantId`, `gameInstanceId`, `characterId`, and `traceId` to follow the log chain: Game Session warning -> Game Logic typed failure diagnostic -> downstream stack trace.
- Use local or PR-attached transcripts from manual runs to validate that current behavior matches the documented `LOOK` contract and to tune the Game Session deterministic text projection. The local Game Logic `LookResultRenderer` remains useful for fixture/diagnostic comparison only.

## Regression verification

- Run `./gradlew crossServiceTest` to exercise the WebSocket and Telnet regression suites; they emit the `gamesession.command.look.*` meters and preserve the owner-bound structured-result and `PlayerOutput`/text-projection proof described above so the automation also validates instrumentation coverage.
- The cross-service target captures the same metrics/log tags documented here, while its end-to-end assertions retain the canonical player-visible text projection for both transports.
